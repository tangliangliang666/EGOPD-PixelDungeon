## 8. 法杖类武器（失乐园）与 buff 特效开发经验

- **"武器+法杖"复合结构**（失乐园）：`MeleeWeapon` 内嵌 `Wand`（构造时 `new WandOfMagicMissile()` + `identify()`），充能走 `Wand.Charger`：`activate/collect` 时 `wand.charge(owner, 0.75f)`、`onDetach` 时 `wand.stopCharging()`、`upgrade` 时 `updateWand(true)`（同步等级与 maxCharges）；施法委托 `wand.execute(hero, AC_ZAP)`。`updateWand` 里 `wand.maxCharges = min(maxCharges+1, 10)` 是老魔杖模式（比普通法杖多 1 上限）。
- **自定义施法效果**（失乐园 onZap）：不复用 `Wand.zapper`（它拦截 self_target），自建 `CellSelector.Listener`：`GameScene.selectCell(zapper)` → onSelect 里 `Ballistica(curUser.pos, target, MAGIC_BOLT)` → `onZap` 分流（敌方/空地=范围伤害、友方/自身=增益）。目标选择 UI 提示走 `prompt()` 返回 `Messages.get(Class, "zap_prompt")`。
- **允许对自身施法**：zapper 里显式 `if (target == curUser.pos)` 直接调效果分支（不走弹道），参考法师储能护盾（SHIELD_BATTERY）的写法。
- **施法后结算**：`curUser.busy()` + 同步 `onZap` + `wand.wandUsed()`（内部 `curCharges -= chargesPerCast()` + `curUser.spendAndNext(TIME_TO_ZAP=1f)`）；无需自绘弹道特效（`MagicMissile.boltFromChar`）——远程直伤的特效在 onZap 里对每个目标显式播放。
- **伤害成长套用**：雷电法杖 `min=5+lvl, max=10+5*lvl`，用 `Random.NormalIntRange`；治疗/护盾套用注魂法杖：友方回血 `round(自身HT*0.05) + 3*lvl`（溢出转 `Barrier` 护盾）、自身护盾 `5+lvl`。
- **buff 百分比属性加成**（祝福）：精准/闪避在 `Hero.attackSkill/defenseSkill` 里乘倍数（参考 HeartFateBuff 的 `accuracyMultiplier/evasionMultiplier`）；**最大生命 +5%** 对 Hero 在 `Hero.updateHT()` 里乘 `HTMultiplier`（attach 时 `updateHT(true)`、detach 时 `updateHT(false)`，buff 移除后重算自动恢复）；对非 Hero 单位直接改 `target.HT/HP` 字段并**存档 htBonus**。
- **buff 文本特殊颜色**（紫罗兰 #EE82EE，与失乐园物品文本一致）：改 `WndInfoBuff` 特判 `buff instanceof 类名` → `titlebar.label(..., 0xEE82EE)` + `txtInfo.hardlight(0xEE82EE)`（同 `WndInfoItem` 对失乐园的处理）。
- **多帧贴图特效**（heaven.png 长矛贯穿）：`Image` 子类 + `frame(texture.uvRect(x1,y1,x2,y2))` 取帧（像素坐标）；`origin` 设底部中心（`origin.set(宽/2, 高)`）实现"底部不动、顶部向上伸展"（`scale.y` 0→1）；**随机选帧**用 `Random.Int(2)` 在 reset 时选一张；生命期用 `Game.elapsed` 递减，`kill()` 结束。
- **跟随单位的标记贴图**（祝福标记/指令目标）：`ItemSprite` 子类（`ItemSpriteSheet.film.get(icon)` 或 `assignItemRect` 注册非标准区域），`update()` 每帧 `place()` 同步到 `target.sprite.center()`（上移像素直接在 place 里减 y）；buff `fx(boolean)` 挂载/销毁，`Char.updateSpriteState()` 读档自动重建。
- **图层顺序**：`GameScene` create 中 `floorEmitters`（角色**之下**）→ `mobs`（角色）→ `emitters/effects`（角色**之上**）。需要贴图在角色之下挂 `floorEmitters`（新增静态方法 `floorEmittersAdd`），之上挂 `effect`。标记贴图不透明就不要调 `alpha()`（指令目标是半透明 `alpha(0.5f)`）。
  - ⚠️ `effect` / `effectOverFog` 形参是 **`Visual`**，而 `Group`(→`Gizmo`) 不是 `Visual` 传不进去；`floorEmittersAdd` 已于 2026-09-11 **放宽为 `Gizmo`**（唯一调用点 `BlessingMarker` 零改动）→ **「渲染在角色之下」现在可直接挂 `Group`**。`GameScene.mobs`/`effects`/`floorEmitters` 都是**私有实例字段**；往角色层挂非 Visual 的 Gizmo 用 `target.sprite.parent.add(gizmo)`（= `GameScene.mobs`，参考 `MasterpieceShow.ensureVisual`）；`sortMobSprites()` 把 mobs 内**非 Visual 成员排到队尾** → 同组但渲染在角色之上。
  - ⚠️ **同一层内无法与角色交错**：要「一部分贴图在角色前、一部分在后」必须拆成两个组挂不同层（`Group.add()` 会自动把节点从原组摘除 → 换层一行搞定）。泪剑「背身层」即此范式：本组挂 mobs（角色之上）+ `behind` 组挂 `floorEmitters`（角色之下），按「是否与朝向同侧」逐帧换层。
  - **全屏屏幕空间滤镜怎么做到「压住画面但不遮 UI」**（2026-09-14 `HeatVignette`）：`Group.draw()` 严格按 `add()` 顺序绘制，而 `GameScene.create()` 里 `add(cellSelector)` 之后就是第一件 UI（`add(menu)`）——把滤镜 `add()` 在这一行**之后、UI 之前**即可（世界层在它下面被着色，状态栏/工具栏/动作条/日志/窗口全在它上面）。它必须自带 `camera = PixelScene.uiCamera`（默认继承 `Camera.main` 会跟着英雄滚动，而「屏幕边缘」要求屏幕空间），并按 `scale = (uiCamera.width/texW, uiCamera.height/texH)` 把贴图拉伸铺满（`Image` 没有 `size()`，改 `scale` 比改 `width/height` 省掉 `updateVertices()`）。渐变色罩用**一张白色径向渐变贴图 + `hardlight(color)` 染色**（片元是 `tex * uColorM + uColorA`，默认混合 `SRC_ALPHA/ONE_MINUS_SRC_ALPHA` ⇒ 按 alpha 给画面掺色）；贴图用 `TextureCache.create(key, w, h)` 后直接写 `texture.bitmap`（libGDX `Pixmap`，**RGBA8888：R 在高位**，要**非预乘**＝RGB 恒白、只让 A 走渐变），不手动上传也安全（`create` 只建对象 `id==-1`，其 `filter/wrap` 见未生成会跳过 GL；真正上传在首次 `bind()`）。
  - **屏幕空间「热浪扭曲」＝换掉全局着色器，别自己开 FBO**（2026-09-14 `NoosaScriptWarp`）：noosa 没有后期处理管线，折射/模糊这类整屏效果的正确做法是**改 shader**——新建 `NoosaScriptWarp extends NoosaScript`（片元里按屏幕位置偏移采样 UV），再让 **`NoosaScript.get()` 与 `NoosaScriptNoLighting.get()` 在开关打开时返回它**：这两处是所有 `Image`/`Tilemap`/`Text` 的着色器汇聚点（`Image.script()` 只有一句 `return NoosaScript.get()`），改一处即覆盖全部世界元素。**「谁被扭曲」靠每帧开/关**：`GameScene.draw()` 的**第一句**打开、**最后一件世界层元素的 `draw()` 第一行**关掉 ⇒ 世界被折射而 UI 纹丝不动，UI 侧无需任何处理。**开关一定要放在 `draw()` 而不是 `update()`**：`Game.render()` 的顺序是 `resetCamera() → draw() → step()(update)`，若在 `update()` 里开关，下一帧开头那两句 `NoosaScript.get().resetCamera()` / `NoosaScriptNoLighting.get().resetCamera()` 也会被换成扭曲脚本，普通脚本的相机缓存就再也清不掉（UI 会用上过期矩阵）。四个坑：①把 `NoosaScriptNoLighting` 的消费者换成带光照的 shader 前，先确认它们传的是**恒等光照**（`Tilemap`/`FogOfWar`/`SkinnedBlock` 都只传 `Visual` 默认值 `rm=gm=bm=am=1, ra..=0`，等价，观感不变）；②**新脚本必须每帧清相机缓存**——`NoosaScript.camera()` 只在相机**对象**变化时才上传 `uCamera`，而 `Camera.main` 是同一个对象、`matrix` 数组是原地改写的，全靠 `Game.render()` 每帧的 `resetCamera()` 才跟得上镜头，新脚本要自己加一句 `XxxScript.resetCameraCache()`（否则画面从此再不跟随相机滚动）；③**别用 `gl_FragCoord`**（部分移动 GPU 只有 mediump 精度，1080p 下误差可达数像素），在顶点里输出 `(uCamera*uModel*aXYZW).xy` 当 `vScreen` 更准也更省；④相位用 `2π` 回绕且**时间系数一律取整数**（1/2/3），回绕点上才连续不跳变。开关关掉时整条链路回到原 shader，零开销。
  - **屏幕空间的粒子（沿屏幕边缘铺火苗）**：`Emitter` 的 `camera = PixelScene.uiCamera` 即变为屏幕空间（粒子坐标直接是 UI 像素），位置用**归一化坐标**每帧换算 `uiCamera.width/height` ⇒ 窗口尺寸变化自动跟随（但 `uiCamera` 在 resize 时会被重建，所以每帧重认一次 `emitter.camera`）。`Emitter` 必须 `autoKill = false`：`update()` 里有 `else if (started && autoKill && countLiving()==0) kill()` —— 一旦 `on=false` 清空它就**自杀且永不复活**，凡是要手动开关的发射器都不能让这条生效。发射参数（颜色/方向/大小）**要为每条线各建一个 `Emitter.Factory`**（匿名内部类捕获方向，颜色/速度在 `emit()` 那一刻从外层现读）：`Factory` 是发射时现取的，若用一个静态 `FACTORY` + 静态字段喂参，几条方向不同的线会在同一帧里互相覆盖。密度调节＝改 `interval` 后 `startDelayed(factory, interval, 0, 0f)`（**`delay=0` 才会立刻产出第一颗**），且**只在变化超过 ±15% 时才重设**——每帧重设会不停重置发射计时器，看起来像零星乱冒。
  - **「跟随角色的持续粒子」别自己 `new Emitter`，借 `CharSprite.emitter()`**（2026-09-14 复仇账簿「仇怨」紫粒子）：`target.sprite.emitter()` 从 `GameScene.emitters` 组里领一个发射器并 `pos(贴图)`（自动跟随移动、`fillTarget=true` ⇒ 在贴图矩形内随机点发射），`pour(factory, interval)` 即持续产出。要点：①**重建判据用 `exists` 而不是 `parent != null`**——`Group.destroy()` 只递归 `destroy()` 子节点、**不清 `parent`**，所以换层后旧发射器 `parent` 仍非空但 `exists` 已是 false；②重建时机不用自己找：英雄贴图重建时 `HeroSprite()` 构造 → `CharSprite.link()` → `Char.updateSpriteState()` 会对**所有 buff** 跑一遍 `fx(true)`，所以把「建/重建」写在 `fx(boolean)` 里、再在每回合 `act()` 里兜底调用一次即可（`GameScene.create()` 里 `scene = this` 早于 `new HeroSprite()`，开局就能拿到发射器）；③停用只写 `on = false`（在飞的粒子自然消亡后由 `autoKill` 自毁），**别 `kill()`**——那会把满屏粒子一下抹掉；④`Buff.detach()` 只在 `target.sprite != null` 时才回调 `fx(false)`，读档期间 sprite 为 null ⇒ 覆写的 `detach()` 里要自己补一次停止；⑤静态常量放外层类（**Java 11：非静态内部类里只允许 `static final` 常量表达式字段**）；⑥「向四周散发」＝`speed.polar(Random.Float(PointF.PI2), Random.Float(min,max))` + 一点上浮 `speed.y -= r`，工厂 `lightMode()` 返 true 走加色混合（`PseudoPixel` 是 1×1 实心贴图，`size(n)` 就是 n×n 像素）。
- **静态 `Image` 要水平镜像只能 `scale.x = -1`**：`Image.flipHorizontal` 是裸 public 字段，只在 `frame()`→`updateFrame()` 时才写进顶点，静态图构造后再赋值**完全无效**（`CharSprite.turnTo()` 敢直接改字段，是因为它每帧动画都会重新 `frame()` 覆盖顶点）。旋转+镜像的组合：noosa 变换线性部分 = `R(angle)·S(scale)`，屏幕 y 向下故**正角=顺时针**（"屏幕逆时针 45°"写 `-45f`）；`R(+45)·S(-1,1) ≡ M_h·R(-45)` 正好是正向结果的水平镜像。**`origin` 是「平移量 + 转轴」二合一**（`updateMatrix()` = `T(x,y)·T(o)·R·S·T(-o)`）：要以**非中心点**为轴（如泪剑的 (5,5)）必须 `origin.set(5,5)` **且**定位写成 `x = 目标点x − origin.x`——两处成对改，只改一处 → 贴图整体偏移/转轴错位。`originToCenter()` 内部即 `origin.set(width/2, height/2)`（用**原始 width/height 字段**，不含 scale），故轴心换成任意点后 `scale.x = -1` 仍以该点对齐（别用 `width()`，那个会乘 `scale.x`、朝左变负）。
- **贴图特效里的「时间」常量要拿真实移动参数标定**：`CharSprite.DEFAULT_MOVE_INTERVAL = 0.1f` 秒/格、一格 16 像素 ⇒ **约 160 像素/秒**（全工程无任何 `setMoveInterval` 调用点，恒为默认值）。凡「延迟 N 秒」「持续 N 秒」的视觉参数，先换算成**像素/格**再定值——否则很容易做出落后两三格的拖尾（残像纠缠的 `DELAY_STEP` 就是这么标出来的：0.07s ≈ 11px ≈ 2.8 格）。
- **场景销毁会递归清 `parent`，可据此判断「视觉是否随场景销毁」**：`Game.switchScene()` → `scene.destroy()` → `Group.destroy()`（先 `super.destroy()` 把自己 `parent` 置 null，再对每个成员递归 `destroy()`）⇒ 挂在 `floorEmitters`/`mobs` 的自定义视觉在换场景后**全部 `parent == null`**，这正是「重建判据写成 `parent == null`」可靠的原因（`fx(true)` 里据此重建即可）。⚠️ `Group.destroy()` 同时把 `members` 置 null ⇒ **销毁过的组不可再 `add()`**（NPE），惰性挂载时 `parent == null` 一律新建组。
- **`Group.recycle(Class)` 只发槽位、不调 `reset()`**：拿到的粒子必须自己 `revive()` + 复位 `am`（`revive()` 只重置 exists/alive，不还原透明度，否则复用首帧会沿用上一世临死时的 `am`）+ 位置/颜色/尺寸。`Group.update()/draw()` 会递归成员，但只处理 `exists && active`。
- **跨组挂载的节点要自己回收；已 `destroy()` 的组不可复用**：把子节点挂到别的组（如 `floorEmitters`）后，它**不再随本组** `killAndErase()`/`destroy()` 一起清 → 覆写 `kill()` / `destroy()` 为「先遍历自己的列表逐个 `killAndErase()`，再 `super`」。`Group.destroy()` 会把 `members` 置 null（之后再 `add()` → NPE），故惰性挂载时若 `parent == null` 一律**新建**组、别复用旧对象。`Gizmo.destroy()` 只把 `parent` 置 null（**不置 `exists=false`**，那要 `kill()`）→ 判断「视觉是否已随场景销毁」看 `parent != null` 就够。
- **`Char.restoreFromBundle` 顺序 = 反序列化时已调 `restoreFromBundle` → 之后才 `attachTo`**：**别在 `attachTo` 里写字段默认值**（会覆盖读档值）；"空值兜底"放 `act()`。
