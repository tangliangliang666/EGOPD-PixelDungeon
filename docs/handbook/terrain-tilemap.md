# 地图贴图 / 分层 tilemap（原 AGENTS.md §3 地形段）

> 定位：`python _chk/docfind.py <关键词>`；或 `grep -n` 本文件。
> 本文件是长尾原文，**按需定点读取，不要整读**。

- **地图贴图＝「分层 tilemap + 跨格拼帧」**（2026-09-18 调研，核心类是 `tiles/` 包）。图集 `assets/environment/tiles_*.png` 是 **256×256＝16×16 帧网格、每帧 16×16px**，`DungeonTilemap extends Tilemap` 用 `TextureFilm(tex, 16, 16)`；`DungeonTileSheet` 用 `xy(列,行)`（**1 基**，与物品图标同规则）按"同一地形的不同图层角色"分行：**行 1-3 地面/水/深渊、行 4-5 FLAT_*（平面版）、行 6-9 RAISED_*（抬高地形本体）、行 10-12 WALL_INTERNAL_*（墙内部，全黑）、行 13-14 WALL_OVERHANG_*（墙檐）、行 15-16 DOOR/OTHER 的 OVERHANG 与 UNDERHANG**。`Tilemap.updateVertices()` 只是把第 (col,row) 格的 quad 铺在 `(col*16,row*16)`，**帧本身永不越格** ⇒ 任何"比一格高"的视觉都必须靠**相邻两格各画半截**拼出来。
  - **三个同 map 的 tilemap，靠 z 序+不同帧分工**（`GameScene.create()` 里的装配顺序）：`DungeonTerrainTilemap`（在 `terrain` 组，**处于角色之下**）画地面+抬高地形本体+墙的正面；`RaisedTerrainTilemap`（**在角色之上**）画抬高地形的"下悬"；`DungeonWallsTilemap`（**在角色之上**）画墙内部黑块+**上一格**的"墙檐/草檐"。层序实测：`terrain(water→tiles→customTiles→visualGrid→terrainFeatures)` → `levelVisuals` → `floorEmitters` → `heaps` → `mobs`(hero) → **`raisedTerrain` → `walls`** → `customWalls` → `levelWallVisuals` → `wallBlocking` → `fog`。
  - **一个高草格会被画 5 遍**（缺省非 ALT 帧的清单，来自 `_chk/grass_sandwich.py` 实测）：① `DungeonTerrainTilemap` → `RAISED_HIGH_GRASS` **122 = `xy(11,8)`**（草皮，整格）；② `TerrainFeaturesTilemap` → **第 `9+16*stage` 帧**（halls 0-4 期→`xy(10,1)`/`xy(10,2)`…，在 **terrain_features.png**，草丛整株占 0~14 行）；③ `mobs` 角色贴图；④ `RaisedTerrainTilemap` → `HIGH_GRASS_UNDERHANG` **250 = `xy(11,16)`**（本格，占 0~10 行）；⑤ `DungeonWallsTilemap` → `HIGH_GRASS_OVERHANG` **234 = `xy(11,15)`**（**画在本格、来源却是下方那一格**，占 8~15 行）。**注意 ② 与 ④ 的第 0~10 行是同一批像素**：features 在角色之下先画一遍当背景，raised 再在角色之上画一遍 ⇒ 站进草里时上半截"糊"在身前，正是这个重复绘制造成的。
  - **「两格高的草」＝三件事叠加**（已用像素级复刻核验，见下）：①**拆帧**——草丛总高约 19px，被切成 `HIGH_GRASS_UNDERHANG`（OTHER_OVERHANG+18，**只画第 0~10 行**）与 `HIGH_GRASS_OVERHANG`（+2，**只画第 8~15 行**）；②**跨格**——UNDERHANG 画在草格自己、OVERHANG 画在**上面那一格**（`DungeonWallsTilemap` 在 y-1 格判 `map[pos+mapWidth]==HIGH_GRASS` 得到），两帧在屏幕空间连成一条连续草叶带 ⇒ 视觉上顶到上一格中部；③**z 错位**——草皮 `RAISED_HIGH_GRASS` 在 terrain 组（角色之下）、草叶在 raised/walls 组（角色之上）⇒ 产生遮挡纵深。**⚠️ 算遮挡前必须复刻 `CharSprite.worldToCamera` 的落点**：`perspectiveRaise = 6/16`（`sprites/CharSprite.java:77`）⇒ `y = (行+1)*16 - 贴图高 - 6`，即 **16×16 的格子只有 12×15 的角色贴图被整体抬高 6px，占 world y = 行*16-5 ~ 行*16+9**：**头探进上一格 5px、脚离本格底 6px**。这就是为什么"草能藏人"——抬高 6px 正好让角色**陷进草叶带**里。按正确落点实测（`_chk/grass_sandwich.py`）：
    - 英雄站**高草格本体**（其上一格、下一格也是高草）：被盖 **88/122 px ≈ 72%**——`r0~r4`（头/肩）来自**他自己脚下那丛草的 OVERHANG**（画在**上一格**里，见下条），`r5~r14`（身体/腿）来自本格 UNDERHANG；只余零星像素透出。
    - 英雄站**普通地面**、上一格与下一格都是高草：被盖 **7/122 px ≈ 6%**，只有 `r13~r14`（脚尖），来源是**下方那格**的草 OVERHANG（它只往上探 8px）。
    - **上面那格的草对英雄零影响**（它的 UNDERHANG 在 world `(行-1)*16+0~10`、OVERHANG 落在**再上一格**，与英雄贴图顶边差 1px 擦肩而过）⇒ 「上下都是高草」里**只有下方那格参与遮挡，上方那格纯背景**。
    - 注意 **OVERHANG 的种子取的是「草格自己的 pos」**（`walls_visual` 里传 `pos+mapWidth`）⇒ 同一丛草在「本格 UNDERHANG」与「上一格 OVERHANG」拿到的 ALT 变体一致（122/125、250/253、234/237 配对），上下两块不会错版。换行/加新地形照这个套路：**图集里补 FLAT / RAISED / WALL_OVERHANG / WALL_INTERNAL 四组帧 + 三处 `getTileVisual` 分支**（本作钻石矿墙 `MINE_DIAMOND` 就是这么接的，帧号 256~287 在两行扩展区，见 docs/features.md）。
  - **新增一种地形（尤其草皮）的完整流程见 `docs/terrain-creation-guide.md`**（含手绘速查表、逐帧核验工具、常见坑）。**画房间地形（而不是画贴图）用 `docs/terrain-editor-guide.md` 里的可视化编辑器**（`tools/terrain-editor/index.html`，双击即用，能直接生成可编译的 `StandardRoom.paint()`）。本文档只留四条最容易漏的红线：
    1. **一个楼层只能有一张图集**：`DungeonTerrainTilemap` / `RaisedTerrainTilemap` / `DungeonWallsTilemap` 三者都是 `super(Dungeon.level.tilesTex())` ⇒ 同一张图必须同时供地面、抬高地形、墙、门、草使用，**不存在「草来自 A 图、墙来自 B 图」**。
    2. **草叶细节层是全局唯一的，不跟你换图集**：`TerrainFeaturesTilemap` 固定用 `environment/terrain_features.png`（256×128＝8 行，按 `stage=(depth-1)/5` 选行：0→高草帧 9/10、1→25/26、2→41/42、3→57/58、4→73/74），**与 `tilesTex()` 无关**。想让草叶也完全自己画 ⇒ 新开一个地形 ID，并且**不要**给 `TerrainFeaturesTilemap.getTileVisual` 加分支（它默认 `return -1`＝该格在这一层什么都不画），把草叶全部画进自己的图集（`Terrain.MINE_DIAMOND` 就是这么做的）。
    3. **`directFlatVisuals` 必须补新地形条目**，否则 `WndInfoCell.cellImage → DungeonTerrainTilemap.tile(pos,tile,flat=true)` 里 `directFlatVisuals.get(tile)` 返回 `null`、传给 `int` 形参**自动拆箱 ⇒ NPE**：表现是**点一下这个格子就闪退**（报错现场离病因最远的一处）。
    4. **帧号的行位置由常量写死**（行 1-3 地面/水/深渊、4-5 FLAT、6-9 RAISED、10-12 内部、13-14 墙檐、15-16 檐/下悬），所以**新图集必须保持这套 16 行布局**。六张分区图集（sewers/prison/caves/city/halls/lob）里"全部空白"的帧共 52 个，其中 21 个是保留或被采矿层占用的（`32` 纯水槽、`76~79`、`132~143`、`244~246`、`252`），**真正可随便用的只有 31 个**（名单见指南 §2.4）；更稳的是走「复制原图集 + 向下追加行」（原 256 帧全保留，新帧从 `xy(1,17)=256` 起），先例 `tiles_caves_crystal.png`（256→288）。
  - **草地分帧的「行 → 世界 y」映射是固定的，高度可自定**（2026-09-18 实测）：`OVERHANG` 帧内 row k → 世界 y = `T-(16-k)`（T＝草格顶边；row15 紧贴 T、row0 在 T 上方 16px）；`UNDERHANG` 与 `terrain_features` 帧内 row k → `T+k`。原版草总高 19px ＝**草地格内 11 行（UNDERHANG row 0..10）＋高出顶边 8 行（OVERHANG row 8..15）**；要加高就加"高出顶边"那一半（OVERHANG 最多用满 row 0..15＝顶格 16px），**别把 OVERHANG 的有效行挪进 0..7**——那一段会被画到*再上面一格*的中上部，看起来像草长到了远处。绘制配方：草皮帧必须**满格 256px 不透明**（半透明会漏出背景）；`UNDERHANG` 前景必须 **alpha=255 实心**（否则透出角色身体，像幽灵），且它的 row 0..10 **直接复制 `terrain_features` 草丛的同一批像素**（实测两者掩码完全一致——原版就是"同一株草丛在角色**之下**画一遍当背景、在角色**之上**再画一遍当前景"）；`OVERHANG` 的 row13..15 用**满宽半透明**做「草皮顶檐」（颜色贴近草皮、row13 是一道暗线），row8..12 才是收窄的草尖剪影。
  - **ALT 变体必须在 `commonAltVisuals` 里登记齐全**：`RaisedTerrainTilemap` 与 `DungeonWallsTilemap` **各自独立**调 `getVisualWithAlts`，只登记一半会让「本格下悬」与「上一格草檐」随机到不同变体 ⇒ **上下两块错版**（原版是三三配对：122/125 ↔ 250/253 ↔ 234/237）。
  - 其余按需接线：`chasmStitcheable` / `waterStitcheable`（缝合沿）、`wallStitcheable`（新地形当墙用时才算墙）、`GridTileMap:49`（网格视图）、`Level:1253` 的 `case Terrain.HIGH_GRASS: … HighGrass.trample(...)`（踩草）、`Level` 子类覆写 `tilesTex()`、`RegularPainter.paintGrass` 只写 GRASS/HIGH_GRASS（铺新地形要自己在 `decorate()` 里后处理，先例 `MiningLevelPainter` 放钻石矿）。
  - **`flat=true` 分支只给「看小图」用**：`DungeonTerrainTilemap.tile(pos,tile)` → `WndInfoCell`（查看格子）、`TerrainFeaturesTilemap.tile` → `WndInfoPlant`/`WndInfoTrap`（查看植物/陷阱）以及鼠标悬停，走 `directFlatVisuals`（行 4-5 那批）拿**单帧平面图**；游戏内地面渲染一律 `flat=false`。
  - **配套机制**：`DungeonTileSheet.tileVariance[]` 按 `Dungeon.seedCurDepth()` 逐格生成 → ≥50 用 ALT 帧、≥95 用罕见 ALT（同地形不呆板）；**水不走 tilemap**（`DungeonTerrainTilemap.needsRender` 跳过纯 `WATER` 帧，水体是 `SkinnedBlock` 动画层，tilemap 只画水的缝合边）；`WallBlockingTilemap`（`wall_blocking.png` 4 帧：右/左/全/下）在墙旁画阴影补"挡视线"的高度感（作者注释自认是 FoW 不足的补丁）；`FogOfWar` 是另一张按视野半径刷 alpha 的 `Image`；`GridTileMap` 画对齐网格。
  - **抬高格子的坐标**：`DungeonTilemap.raisedTileCenterToWorld(pos)` 把中心 y 从 `(行+0.5)*SIZE` 改成 `(行+0.1)*SIZE`（**上移 0.4 格**），凡"落在草上的光束/爆炸/落点"都该用它（`SuperNovaTracker`、`Beam.SunRay`、`Lightning.Arc`、`Tengu` 炸弹等 11 处已在用），否则特效会落在抬高地表的下方。
  - **核验工具**（纯 Python、无 PIL 依赖，直接解 PNG）：`_chk/tileframe_dump.py <png> <列,行>…` 把任意 16×16 帧打成 ASCII（透明/半透明用空格与 `.` 区分）；`_chk/tilemap_sim.py` 复刻了三个 `getTileVisual`，`_chk/tilemap_occlusion.py` 把角色画成品红测遮挡、`_chk/tilemap_render_png.py` 用真实贴图渲染整张场景到 `_chk/tilemap_render.png`、`_chk/grass_sandwich.py` 是**「上下都是高草夹住角色」具体实例**（逐格打印每层的 帧号/`xy(列,行)`/来源 png/帧内不透明行，并渲染 6 张分层面板 + 遮挡差异图 → `_chk/grass_sandwich.png`、`grass_sandwich_floor.png`）。注意 `load_png` 已支持**调色板 PNG（PLTE/tRNS）**——角色贴图（warrior.png 等）是调色板格式，只支持 RGBA 会把角色读成全黑。
  - **画完新地形怎么自检**（2026-09-18 新增）：`_chk/terrain_tileset_check.py <png> [<角色>:<帧号|列,行> …]` 按「地形角色」逐帧断言——`ground`/`raised`/`flat` 必须满格 256px 不透明、`overhang` 有效行不该落在 0..7、`underhang` 不该从 row≥8 才开始，并打出 ASCII 供目检；不带帧参数时输出总览＋**所有空白帧号与 x,y 坐标**。`_chk/grass_frame_audit.py` 逐行打印草帧的不透明像素数/平均色，并判定「OVERHANG 与 UNDERHANG 是否互为同一丛草的上下两半」「UNDERHANG 与 features 草丛是否同像素」——**画完新草后拿它对照原版**（改路径/帧号即可）。
