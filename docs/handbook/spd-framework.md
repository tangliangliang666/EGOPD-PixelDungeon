## 4. SPD 框架机制经验

- **永久 buff**：`Buff.affect` 不带时长会立刻分离（FlavourBuff）；永久效果用大时长（`99999f`）或覆写 `act()`。
- **每回合逻辑**：`Buff.act()` 默认 `diactivate()`（不走 TICK）；覆写 `act()` 时记得 `spend(TICK); return true;`。
- **无视护甲伤害**：`Char.damage(dmg, src)` 不结算护甲（用于"无视防御"类攻击）；普通攻击走 `attackSkill/defenseSkill/drRoll` 全流程。
- **三个「对英雄生效」的宿主钩子**（2026-09-12「泪锋的加护」用；都是就地扩展 Hero/KindOfWeapon 里已有的方法，无需新事件系统）：①**护甲最低减伤** → `Hero.drRoll()` 里 `belongings.armor()` 那段的 `Random.NormalIntRange(DRMin(), DRMax())`：要「只抬保底」就抬 `DRMin` 侧，并**必须补 `if (armMax < armMin) armMax = armMin;`**，否则区间反了；②**受击计数** → `Hero.damage(int, Object)` 中 `if (effectiveDamage <= 0) return;` **之后**（`preHP = HP + shielding()` 已把护盾算进 effectiveDamage ⇒ 被盾完全吃下的那一下也算「受击」），但**必须过滤 `src instanceof Char`**，否则流血/毒/燃烧这类每回合跳一次的 DOT 会瞬间把计数刷爆；③**只削武器攻击力上限（不动下限）** → `KindOfWeapon.damageRoll(Char)` 里 `Hero.heroDamageIntRange(min(), max())`：只削 `max()` 侧、削到低于 `min()` 时取平，注意此处是 augment / 力量加成**之前**的原始掷值（`MeleeWeapon.damageRoll` 在其上再乘 augment）。
- **「受伤充能 / 击杀充能」两个事件钩子**（2026-09-13「复仇账簿」用）：①**受伤量** → `Hero.damage()` 已在算 `int effectiveDamage = preHP - postHP;`（`preHP = HP + shielding()`）：若只想要**真正从 HP 扣掉的血**（护盾吃下的不算），另外自己前后各存一份**不含护盾**的 `HP` 快照再相减，位置放在该行之后即可；②**击杀** → `Mob.die()` 里 `if (cause == Dungeon.hero || cause instanceof Weapon || …)` 的英雄击杀分支（与 `TinyGalaxy/SmilingBlade/RingMasterLoot.onEnemyKilled` 同处），**必须在 `super.die()` 之前**读 `mob.HT`（之后 HP 归零、精灵被回收）。两处都无需新事件系统。
- **「命中 / 未命中」两个事件钩子**（2026-09-14「仔细看好！」用）：`Char.attack` 里命中分支与 else 分支各一处。**命中钩子放在 `enemy.damage(effectiveDamage, this)` 之后**——只有那里才读得到「本击是否击杀」（`!enemy.isAlive()`）；未命中钩子放在 else 分支 `onHeroAttackResolved` 之前。两个钩子共用 `Char.attack` 内的 `this == Dungeon.hero` 判定即可强转 `(Hero) this`（同 577/675 行的既有写法）。**相关数值汇聚点**：精准乘区只在 `Hero.attackSkill()`、力量只在 `Hero.STR()`（这两个是全工程唯一入口，加 buff 加成都写在那里）。**要按"这一击打了多少伤害"判定**（2026-09-16「如数奉还」）就直接用同作用域里的 `effectiveDamage`（第 554 行声明、`enemy.damage(effectiveDamage, this)` 的那个值，已含护甲减免 / 易伤 / 攻防 proc），把它当参数传给需要它的钩子即可——**别再自己前后快照 HP 相减**，那会把「打到护盾上」「目标残血被溢出击杀」这类情况算成不同的数。
- **「攻击命中」其实有两条互不重叠的路，做「挨打就记一笔」类特性必须两条都收口**（2026-09-17「怨恨标记」补远程）：①**近战 / 投掷武器** → `Char.attack(...)` 的命中分支（4 参 `hit(this, enemy, accMulti, false)`，`Hero.shoot` 的投掷也在这里）；②**远程 / 法术弹道** → **`Char.hit(Char, Char, boolean)` 这个 3 参重载**。各法杖怪的 `zap()` 都是 `hit( this, enemy, true )` + `enemy.damage(dmg, new XxxBolt())`（萨满 / 术士 / DM100 / 元素 / 眼魔 / 尤格之爪 / 尤格之拳 / 哨戒室哨兵），**根本不过 `Char.attack`**；3 参重载只有这些调用方（全仓 11 处），所以它是「远程弹道」的天然收口点，一处即覆盖全部（日后新怪也不会漏），且与 4 参重载互不重叠、不会重复叠层。3 参重载里的 `magic ? 2f : 1f` 是「魔法弹道命中加成」，别当成命中率。**代价**：命中判定早于伤害结算，这里拿不到「这一击打了多少」——要按伤害判档的追加效果只能留在 4 参那条路（`Char.attack` 里用 `effectiveDamage`）。
- **「按最终伤害做夹取」的天赋必须先扣掉护盾，否则等于给护盾也上了保命**（2026-09-17「过人的毅力」修正）：护盾是在 `Char.damage` 里**伤害定稿之后**由 `ShieldBuff.processDamage → absorbDamage` 消耗的（`Hero.damage` 里 `dmg` 已定稿、护盾一点没动），所以在 `Hero.damage` 中段夹取 `dmg` 会把护盾那一份也削掉——护盾「本该吃满却没吃满」，等于替盾也挡了刀。正确口径：`absorbed = min(dmg, hero.shielding())`（用 `super.damage` 之前的 `shielding()`，与 `processDamage` 的吸收量完全一致），只对 `dmg - absorbed` 这一部分做夹取，返回 `absorbed + capped`。**饥饿伤害（`src instanceof Hunger`）绕过护盾**，`shielding()` 要按 0 传，否则口径与结算不一致（`Hero.damage` 里 `preHP` 那两行也是这么特判的）。
- **武力戒指的「+N」在伤害公式里是等级 N+1，且等级 ≤0 会被当成诅咒**（2026-09-17「傲人肌肉」踩坑）：`RingOfForce.damageRoll` 的等级来自 `getBuffedBonus → RingBuff.buffedLvl() → soloBuffedBonus()`，而它（未诅咒时）返回 `buffedLvl()+1` ⇒ **+0 戒指 = 等级 1**、+1 戒指 = 等级 2。另外 `min()/max()` 里有一句 `if (lvl <= 0) tier = 1; //tier is forced to 1 if cursed`（**原版就有，不是 mod 加的**）——等级为 0 时 `tier(hero.STR())` 被整体丢弃，伤害钉死 1~10、**力量一概不算**。所以任何「伪造一枚 +N 武力戒指」的实现（如「傲人肌肉」）伪等级必须填 **N+1**；填成 `点数-1` 就会在 +1 点时掉进诅咒分支，比空手还弱、且「仇怨」那 +12 力量完全看不到。
- **「无法闪避」类天赋必须照抄磐岩附魔的两处结构**（2026-09-14「你犯规了」）：①`Hero.defenseSkill()` 末尾 `return 0`（`defRoll` 恒 0 ⇒ 必中），但取「真实闪避值」时要用一个**自己的 testing 开关**跳过归零（磐岩用 `Stone.testingEvasion()`，天赋不要复用它的开关，免得两者互相干扰）；②**`FloatingText.getHitReasonIcon()` 必须补一条 `defRoll == 0` 的早退**——那里原本只对磐岩附魔早退（`defRoll == 0 && arm.hasGlyph(Stone)`），不走早退就会进入 `arm.evasionFactor(...)` 段、拿归零后的 `defenseSkill()` 当分母 ⇒ **0/0 = NaN** 污染命中原因 map（`Collections.sort` 的比较器返回 NaN 还会破坏传递性），并且该 map 的结果最终会变成伤害浮字图标（`Char.damage` 里读 `hitMissIcon`）。③防御侧的换算写在 `Hero.defenseProc(Char enemy, int damage)`（**唯一同时拿得到攻击者与伤害的防御侧钩子**，磐岩也是走这条路）；若防御方护甲本身带同一附魔要**跳过**，否则同一笔算两次。
- **「等待时获得 X」的两种完全不同的实现——先分清要的是「护甲」还是「护盾」**（2026-09-14「你犯规了」+2 踩坑）：**护甲**走 `Hero.drRoll()`（每回合重掷的随机减伤；原版 `HoldFast`「坚守阵地」就是这条，也正因此中文里「等待时获得护甲」几乎是它的专用说法）；**护盾**走 `ShieldBuff` 子类，在 `Char.damage()` 里由 `ShieldBuff.processDamage → absorbDamage` 被消耗。**判定标准只有一个：它会不会被打光**。三个配套要点：①`ShieldBuff.setShield()` **只抬高不降低**（要累加得用 `incShield`）⇒「不可叠加」用它天然成立；②**补盾钩子绝不能写成每回合轮询**（`act()` 里 `if (等待) refresh`）——等待期间每回合补满 = 常驻减伤，手感立刻变成护甲；正确做法是挂在**产生等待的那个入口**（`Hero.rest(boolean fullRest)`，单击等待与长按休息都经过）补**一次**，让护盾成为一次性资源；③解除判定要用「本回合在执行动作」：`Hero.act()` 开头**先取 `curAction != null` 的快照**再进 `if/else`——各 `actXxx()` 分支末尾会把 `curAction` 置回 `null`，之后再判就恒为 false。另注：`Hero.resting` 只代表**长按休息**（单击等待是 `rest(false)` ⇒ `resting = false`），任何「等待时…」的特性只盯 `resting` 都会漏掉单击等待。
- **新增职业天赋时的三重注册**（2026-09-14 中指长兄 T1）：`Talent` 枚举加常量（图标写**绝对索引**）→ `icon()` 的 `HEROIC_ENERGY` 分支加 `case <职业>` → **`initClassTalents` 的三个 tier switch 每个都要显式 case**。第三点最易漏：三个 switch 的首个分支都是 `case WARRIOR: default:`，漏加就会让新职业**白拿战士天赋**；尚未实现的天赋层级写**空 case**（`break;` 什么都不加），`TalentsPane` 会因 `talents.get(i).isEmpty()` 自动跳过空层，比填占位天赋干净。
- **限时数值的「覆盖式刷新」写法**：要「再次触发直接重置时长、不叠层」，把剩余时长设为 `turns` 用 `spend(turns - cooldown())`（`Actor.spend/cooldown` 都在同一套 `time - now` 语义里，先例 `AdrenalineSurge.reset`），别用 `Buff.prolong`（那是叠加）。
- **「冷却型天赋」的标准范式**（2026-09-15 中指长兄 T2「趁手玩具」）：①冷却用一个 `FlavourBuff` 子类（`public static class XxxCooldown extends FlavourBuff{}`，放 `Talent` 里），`Buff.affect(hero, XxxCooldown.class, N - 1f)` —— **减 1** 是因为本回合自身也占一格（原版 `KindOfWeapon.doEquip` 的 `SwiftEquipCooldown` 用 19f 表达「每 20 回合一次」，是最现成的先例）；②判定集中写在 `Talent` 的静态方法里**返回「本次的代价」**（0 = 免费并已开始冷却 / 1 = 正常），调用方只负责 `hero.spendAndNext(cost)`；③**冷却必须在「这一次免费」上就开始**，不能等冷却结束了才记，否则连点两下会白嫖两次；④想让它可见就给 `icon() { return BuffIndicator.TIME; }` + `iconFadePercent()`（照 `RejuvenatingStepsCooldown`），否则玩家无从知道为什么这次没有被免费。
- **「以英雄为源的伤害」怎么判定**（2026-09-15「报复对象」+20% 用）：`Char.damage(int, Object)` 里的 `src` — ①近战、投掷武器、以及所有写 `enemy.damage(dmg, hero)` 的技能，`src` **就是英雄本人**（`src instanceof Hero`）；②但**法杖的 `src` 是法杖实例而不是英雄**（每个法杖都写成 `ch.damage(damageRoll(), this)`），要让法杖伤害也算「英雄打的」就得额外认一类 `Wand`（安全：游戏里只有英雄会真正用法杖打出伤害，DM300 只借 `WandOfBlastWave.throwChar` 做位移、元素怪走 `CursedWand.effect(null, ...)`）；③**间接伤害不算**——点燃地面后的 `Burning` 烫伤、中毒、流血，`src` 是那些 buff 自己。判定要收敛到 `Talent` 的一个静态方法里，别在 `Char` 里摊开写。
- **`Buff.announced = true` 会自己弹名字，不要再手工弹一次**：`Char.add(Buff)` 在 `sprite != null && buff.announced` 时按 `type` 自动 `showStatus(名称)`（POSITIVE→绿、NEGATIVE→橙、NEUTRAL→白），**对怪物同样生效**。所以「给敌人打标记」这类 buff 只要 `announced = true`，头顶就会自己冒出名字；再自己 `sprite.showStatus(...)` 会**弹两遍**。
- **「免死」型技能状态的标准范式**（2026-09-17 中指长兄盔甲技能「咬紧牙关」）：①**唯一汇聚点是 `Hero.isAlive()` 的 `HP <= 0` 分支**（照抄 `Berserk`：加一个缓存字段，`HP > 0` 时顺手清空缓存），不要在 `Hero.damage` 里自己拦——挂在 `isAlive()` 上，「不触发死亡」的所有下游（能否行动、死亡结算、任务失败）才会自动一致；②**缓存字段 × 卸载顺序是个坑**：`Char.remove(Buff)` 不会回写 `isAlive()` 的缓存，所以状态 buff 必须在**卸载前**先把「还在免死吗」的标志置位（`GritTeethBuff.act()` 先 `bypassed = true` 再 `detach()`），否则缓存里那个已卸载的实例永远说「免死」⇒ 英雄再也死不掉；③状态用 `FlavourBuff` 子类 + `Buff.prolong(...)` 刷新（`prolong` = `affect` + `postpone`，**只延不缩**），把 `act()` 覆写成「置位 → 结算收尾 → `detach()` → 判死」；到期时调度器只会调**一次** `act()`（`FlavourBuff.act()` 本体就是 `detach(); return true;`，可见 `act()` 就是「到点那一刻」的回调，别在里面写每回合逻辑）；④**「某类伤害击穿免死」的挂点**：`Char.damage` 里 `if (HP < 0) HP = 0;` 与 `if (!isAlive()) die(src);` **之间** —— 只有这一刻才判得出「这一击是否致命」，也才来得及在 `isAlive()` 被问起之前把免死作废；判定源收成**两类**：**射线**用类表 `RAY_SOURCES`（`Eye.DeathGaze` 一条同时覆盖邪能魔眼与 YOG 的死亡射线）、**「自伤换成长」**用标记接口 `items/SelfHarmCost`（蓄血圣杯血祭 / 割腕；与 `Talent.perseveranceCap` **共用同一判据**，别再各开一份名单）——否则开着免死去血祭/割腕就是「血量打到 0 也不死 ⇒ 每一下都升级成功」。收尾判死的写法照抄 `Berserk`：`target.die(this); if (!target.isAlive()) Dungeon.fail(this);`。
- **技能想「借用」现成图标帧，用 `ArmorAbility.iconTint()`**（2026-09-17）：`ArmorAbility` 新增 `public int iconTint()`（默认 `NO_TINT = 0xFFFFFF` = 不加），`HeroIcon(ArmorAbility)` 把非默认值按通道归一化后 `hardlight` 上去（`0xFF5AFF` = 保留红蓝、压掉绿的紫色滤镜）。这样「套用怒气图标 + 紫色滤镜」只花一个常量，不必占 `hero_icons.png` 的新帧；`Buff` 侧的同款机制是既有的 `tintIcon(Image)`。
- **「连段 + 击退 + 投掷追击」类技能的时序坑**（2026-09-17「即刻处刑[莱瓦汀]」）：①**击退是异步的**——`WandOfBlastWave.throwChar` 排的是一个 `Pushing` 视觉（`effects/Pushing.java`，`DELAY = 0.15f`），敌人真正的 `pos` 要等这 0.15 秒动画播完才更新；`Pushing.act()` 一上来就 `Actor.remove` 自己，所以 `pushingExistsForChar()` 在动画期间**恒为 false**（它只用来判「同一 tick 内还会不会再推」），靠它、靠调 `actPriority` 都等不到落位，自己写轮询 Actor 更危险（`spend()` 会在同一帧里把 `Actor.now` 一路推快）。**可行做法是插一幕后摇当节拍**：`hero.sprite.attack/operate/zap` 三兄弟都收 `Callback`，拿 `hero.sprite.operate(cell, cb)` 当一拍（英雄贴图的 `operate` 是 8fps×4 帧 = **0.5 秒**，见 `HeroSprite` 第 98 行）在 `cb` 里再读 `enemy.pos` 起飞。②**「投出武器」是纯演出，不要动背包**：把武器实例本身喂给 `MissileSprite.reset(hero.sprite, cell, item, cb)`（`ItemSprite.view(item)` 只读贴图，不消耗也不卸装），角速度走默认的 720°/秒 ⇒ 自然就是「旋转着飞出」；要「按武器面板算伤害」就在 `cb` 里调 `hero.attack(victim, 1f, bonus, Char.INFINITE_ACCURACY)`——此刻主手就是那把武器，`damageRoll()`/`proc()` 会带上它的面板、附魔与附加伤害。参考：`FetalDoctor.deployBomb`（投掷演出）、`Spear.doAbility`（投掷前的 `pushingExistsForChar` 旧写法）。③**⚠️ 多段连段一律做成「渲染线程状态机」——不押贴图回调，更不排 Actor**（2026-09-17「即刻处刑[莱瓦汀]」重写；上一版「主路贴图回调 + 真实时间保底」的**双保险**写法已废弃）：根因比「回调不牢靠」更深一层——**英雄 `busy()` 期间回合线程是停的**。`Hero.act()` 在 `curAction == null` 时只 `ready()` 并 `return false` ⇒ `Actor.process()` 走进 `wait()` 挂起，而 `Actor.current` 仍指着英雄（`Actor.processing()` 恒为 true）；`GameScene.update()` 只在 `!Actor.processing()` 时才 `notify()` ⇒ **英雄持有回合期间回合线程不会醒，任何 Actor 都不会动**。由此两条硬约束：
  - **① `WandOfBlastWave.throwChar` 不能用在英雄自己的回合里**：它排一个 `Pushing` Actor 去落位，敌人的 `pos` 要等回合交出去以后才真的变。本回合内读 `victim.pos` 读到的是**击飞前**的位置 ⇒ 投刀时目标还贴脸（导弹几乎不用飞、一闪而过看不见）、`leapDest` 判「已相邻」⇒ **不跳、就地补刀**；等回合结束 `Pushing` 才把那一记击飞补上（看起来像「击退发生在最后」）。
  - **② 贴图动画一律传空回调**（不能传 `null`）：`CharSprite.animCallback` 是**单槽**的（`attack`/`operate`/`zap` 谁后调谁覆盖，见 [CharSprite.java#L258-L282](file:///d:/PD/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/sprites/CharSprite.java#L258)）；而 `animCallback == null` 时 `CharSprite.onComplete` 会**自动 `idle()` 并调 `ch.onAttackComplete()` / `onOperateComplete()`**——对英雄就是**再打一次真攻击并提前结算回合**，比失约更糟。做法：给所有装饰性动画传一个空 `Callback`（`NO_OP`）。

- **神器的"等级"不要覆写 `level()`**（2026-09-15）：`Artifact.visiblyUpgraded()` 是 `level()*10/levelCap`，而神器 `levelCap` 默认为 **0** ⇒ 让 `level()` 返非 0 会得到 `Infinity`（`Math.round` → `Integer.MAX_VALUE`），格子角标直接炸。要"随英雄等级成长"的等级请另开只读方法（如 `ledgerLevel()`），显示靠自己的 `info()`/`status()`。同理：`Artifact.status()` **只在上限恰好 100 时**才显示 `%d%%`，上限会变（100→200）时必须覆写 `status()`，否则退化成 `87/150`。
- **神器充能上限动态化的读档裁剪陷阱**（2026-09-15）：`Artifact.restoreFromBundle` 里有 `if (chargeCap > 0) charge = Math.min(chargeCap, charge)`。若上限随英雄等级变化，反序列化时字段还是初始值就会把超出部分裁掉 ⇒ **实例初始化 + `restoreFromBundle` 里先把 `chargeCap` 设成理论最大值**，再由 `activate()` / 每回合被动 buff 里的小 `syncChargeCap()` 修正。
- **「神器充能」buff（`ArtifactRecharge`）的唯一入口 = `Artifact.charge(Hero, float)`**（2026-09-15 核查）：该 buff 每回合遍历英雄身上的 `Artifact.ArtifactBuff`（跳过 `isCursed()`＝被诅咒且无魔法免疫的那个），对每个调 `charge(hero, min(1, 剩余回合))` → `ArtifactBuff.charge` → `Artifact.charge(Hero,float)`。**父类默认是空方法** ⇒ 自定义神器不覆写它就完全吃不到这个 buff。`amount` 的语义是「≈1 点/回合」，各神器自带换算系数（原版 0.1~4：`TalismanOfForesight` 2、`MasterThievesArmband` 0.1、`CloakOfShadows` 0.25），**必须按自己 `charge` 刻度的强弱选系数**（泪锋的加护 `chargeCap` 只有 5~10，照抄 0.25 会让一次 30 回合的秘能卷轴直接灌满）。`RingOfEnergy.artifactChargeMultiplier` **不在**这条链路上（只乘在各神器 `act()` 的被动充能里），所以 `charge()` 里不乘它是与原版一致的。**同一神器同时挂了「被动」与「激活」两个 ArtifactBuff 时会被充两次**（原版 `OdinsEye` 的 `eyeRecharge`+`precognition` 即如此；自定义的 `RevengeLedger` 的 `ledgerRecharge`+`Rancor` 也是）——若激活态本身按回合扣充能，就会出现「+2%/回合恰好抵消 −2%/回合 ⇒ 效果永不结束」的漏洞，要照 `ArtifactRecharge` 里排除 `HornOfPlenty.hornRecharge` 的范式把激活 buff 排除掉。

- **「最终伤害值的最后一刀」只能落在 `Hero.damage` 的 `super.damage` 之前**（2026-09-16「过人的毅力」用）：`Hero.damage` 里 `dmg = (int)Math.ceil(dmg * RingOfTenacity.damageMultiplier(this) * SilentPrice.damageTakenMultiplier())` 这一行之后，**全部倍率与护甲减伤都已结算完，而护盾/血量还一点没动** ⇒ 这里拿到的 `dmg` 就是「这一下真正要打进去的总伤害」，`TearSword.onHitTaken` 的受击计数也正是挑在这个位置。**要夹取伤害（上限/下限/归零）必须写在这里、且早于 `super.damage`**：血量归零→`die()` 是在 `super.damage` 内部一次性做完的，事后补血根本来不及（同 §6「对已死目标的守卫必须写在调用方」是同一类教训）。放在这一处的另一个好处是**覆盖面自动拉满**——攻击、环境、陷阱、坠落、毒/燃烧/流血 DOT 全都汇进 `Hero.damage`，一处夹取全管住。
- **「造成的伤害」与「受到的伤害」是两条互不相交的接线**（2026-09-16「野兽狂怒」用）：`Char.damage(dmg, src)` 里 `src` 是**出手方**、`this` 是**挨打方**，而 `Hero.damage` 只可能以英雄为挨打方 ⇒ 同一笔伤害只会走其中一条，"造成 ±X% / 受到 ±X%" 用同一个倍率方法各接一处**绝不会叠乘两次**（对照 §4「以英雄为源的伤害怎么判定」：出手侧统一复用 `Talent.isHeroDealtDamage`，把近战/投掷/技能/法杖一次全框住）。**血量阈值判据一律用整数比较**（`HP * 100 < HT * 50`）而不是 `HP/(float)HT < 0.5f`，与既有 `Talent.tooHotImmune` 同款——浮点比较在边界上会翻车。

- **buff「层数」三件套**（2026-09-15，照 `HuntingTarget` / `Brag` 的惯例）：① 公有字段 `public int stacks`；② 静态入口 `addStack(ch)` / `setStacks(ch, n)` / `stacksOn(ch)`（**只能 `Buff.affect` 之后再设字段**——实例由框架 new 出来，没有带参构造，所以「新建时就是 N 层」的写法要先 affect 再赋值）；③ 覆写 `iconTextDisplay()` 把层数显示到图标上（需求若有 desc 带层数，另覆写 `desc()` 走 `Messages.get(this, "desc", stacks)`，此时文案变成**带参文本、字面 `%` 必须写 `%%`**）。**读档必须夹一次**：`bundle.getInt(key)` 缺键返 0 ⇒ `Math.max(1, Math.min(n, MAX))`，否则旧存档读进来层数变 0、按层数生成的视觉一个都不建（静默失效、不报错）。层数变化后要主动重建「按层数生成的对象」：本工程做法＝`refresh()`＝`clearResidues()` + `fx(true)`，同时把 `fx(true)` 的重建判据从「未建成」扩成「**未建成 或 数量 ≠ 层数 或 没挂上场景**」。

- **整幅贴图的「弯曲形变」（果冻/鞭状摆动）＝ 分层绘制，别指望单 quad**（2026-09-15「依旧果冻人」挑战）：noosa 里一张 `Image` 只有**一个 quad**（4 顶点、4 分量），顶点级变换只能做出**刚性错切**（整张图倾斜），想让轮廓真的弯出一条曲线（底边不动、越往上偏移越大）只能把贴图**按高度切成 N 条横带**、每条整体横向平移。实现落在 `com.watabou.noosa.JellyDraw`（**引擎级新增**，`Image.draw()` 在 `jellyAmp != 0` 时改走它；`jellyAmp == 0` 的普通路径零改动），状态与计时在 `Image`（`jellyWobble(amp, dir, duration, freq)` / `jellyOffset()` / 覆写的 `update()` 里递增 `jellyTime`），游戏侧只管在触发点调这一个方法（本项目入口 `effects/JellyWobble`）。**四个必守要点**：①**局部坐标 y=0 是贴图顶边、y=height 是底边**（见 `Image.updateVertices()`）⇒「脚底不动」＝高度比例取 0 在底边，偏移用 `t²` 加权（取每层**顶边**处的 t 才能让最上面一层恰好达到满幅）；**但「t 从脚底起算」只对 xy 成立，UV 必须按同一个 `1-t` 插值**（`vTop ↔ y=0`、`vBot ↔ y=height`，与 `Image.updateFrame()` 同构）——直接拿 t 插 UV 会把 `frame.bottom` 贴到顶边、**整张图上下颠倒**（已踩，2026-09-15 修复）；②**顶点要写进全局共享的客户端 `FloatBuffer`（`Quad.createSet(SLICES)` + put 若干层 + `script.drawQuadSet(quads, n)`）**，一次 `glDrawElements` 画完所有层——既避开了 `Vertexbuffer`（切场景时 `Game.switchScene()` 会 `Vertexbuffer.clear()` 清掉所有已注册缓冲 ⇒ 静态共享的 GL id 会失效），也**不能**顺手改 `Image` 自己的 `vertices`/`buffer`（`ItemSprite` 的钻石剑附魔流光直接读 `vertices` 当遮罩 UV，会被串味；而摆动结束后 Image 仍要用自己那份原始顶点继续画）；③**相邻层要向下多铺 0.25 像素**（UV 同步多取一点）防浮点接缝，**最底层不能多铺**（会采样越出帧外、串到贴图册相邻帧）；④**不要给「已死/未挂场景」的贴图无限期留着 `jellyAmp`**——计时靠 `update()` 推进，挂在被更新的组里就一定会自愈（`Group.update()` 递归全部成员，被回收复用的精灵最多多抖 0.9 秒）。参数标定照 §8「时间常量拿真实移动参数校准」的老规矩：`0.9s × 8 rad/s ≈ 7.2` ⇒ 极值点 3 个（`⌊7.2/π⌋+1`），甩出去→回摆→过冲，而不是 0.1 秒抖完的「假摆动」。**分层数要跟着幅度走**：相邻层错位量＝`2·amplitude·t / SLICES`，幅度调大而不加层，峰值处轮廓会露出阶梯（现取 `SLICES = 20` / `AMP = 16`，由 `effects/JellyWobble` 标定）。**竖直形变要和横向叠在同一套零点上**：`y = h·(1 − t·(1+squash))` 把「压扁/拉长」也锚在底边，再把压扁量按 `t` 折算成横向鼓出（`BULGE`）——横移 / 压缩 / 鼓出三路形变的零点全在底边，「脚底不移动也不形变」才不会被某一路破坏；竖直必须与横向**差 1/4 周期**（`cos → −sin`），同步缩放只是「呼吸」，不是果冻。**摆动来回次数 = `DURATION × FREQ / (2π)`**（改次数只动这两个常量）。**死亡动画不要**去 28 个 `XxxSprite.die()` 里逐个加（大半会 `super.die()` ⇒ 重复触发），钩在**唯一的** `Char.die()` 里，且必须在 `sprite.die()` **之前**（有的死亡动画会 `killAndErase()` 把精灵摘走）。

- **游戏 BGM 的全局替换钩子 = 引擎层的 `Music.setTrackOverride`**（2026-09-18「角色专属 BGM」）：BGM 的播放点**散落在十几处**（各 `Level.playLevelMusic()`、`YogDzewa`/`DwarfKing` 战斗中途变奏、`AmuletScene` 等），逐个改既容易漏又会污染原版代码。做法是在 `com.watabou.noosa.audio.Music` 里加一个可注册的钩子（`public interface TrackOverride { String override(String requestedTrack); }` + `setTrackOverride`），只在两个**公共入口**生效：`play(String, boolean)` 与 `playTracks(String[], float[], boolean)`。要点：①`override` 返回 `null` **或与请求相同**的曲目都视为「不干预」（这条幂等规则很关键——`playTracks` 命中后内部会再调一次 `play(forced, true)`，幂等才不会打转）；②`playTracks` 命中时整个随机列表被「该曲目单曲循环」取代（`play(forced, true)` 后 `return`，`trackList` 保持 null ⇒ `enable(true)` 重启走 `lastPlayed` 分支，安全）；③`lastPlayed` 记的是**替换之后**的名字，所以开关来回切时能被正确判成「换曲」而重播、同曲时不打断；④**立即生效**＝`HeroBgm.refresh()` → `Dungeon.level.playLevelMusic()`（让当前层重走一遍选曲，请求再经钩子）。游戏侧封装在 [HeroBgm.java](file:///d:/PD/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/HeroBgm.java)：`track()` 在「开关关 / `Dungeon.hero == null` / 英雄不在四位之列」时一律返回 `null`——于是标题、选人、结算、日志这些 `Dungeon.hero = null` 的界面天然不被替换，**「非专属角色设置里不出现该选项」也直接复用同一个判据**（`WndSettings.AudioTab` 用 `HeroBgm.hasBgm(HeroBgm.activeClass())` 决定要不要 `add`）。**素材规格**：自定义 BGM 走 **mp3**（`core/src/main/assets/music/`，Android/iOS/桌面三端的 assets 都指向 core 这一份），44100Hz / 立体声 / **96kbps**（`_chk/import_hero_bgm.py` 一键转码+体积报表）；`DeviceCompat.isiOS()` 那条 `.ogg → .mp3` 替换对已经是 mp3 的名字没有影响。**`Music` 是流式解码**（gdx `Music` 边读边解），文件体积只影响包体与安装占用，**不影响运行时内存**（对照 `Sample`——音效是整段解码进内存的，见 §4 音频条目）。

- **武器「命中音」的唯一钩子 = `KindOfWeapon.hitSound(float pitch)`，不是 `hitSound` 字段**（2026-09-18 双蛇杖随机攻击音）：调用链是 `Char.attack` 命中分支 → `Hero.hitSound(pitch)` → **`belongings.attackingWeapon().hitSound(pitch)`**（多态）→ `KindOfWeapon` 里 `Sample.INSTANCE.play(hitSound, 1, pitch * hitSoundPitch)`。要点：①**改 `hitSound` 字段 ≠ 改行为**——字段只能填**一条固定音**，而且下面那条会让它**根本不被读到**，所以「每次命中随机播一条」这类需求只能**覆写方法**；②**`attackingWeapon()` 的取值顺序是 `thrownWeapon` → `abilityWeapon` → `weapon()`**，而 `MeleeWeapon.beforeAbilityUsed` 会写 `hero.belongings.abilityWeapon = this`（`afterAbilityUsed` 复位）⇒ **武技窗口内 `attackingWeapon()` 是被委托执行武技的那把武器**；对「会变形/会委托」的武器（双蛇杖把武技转给随机形态武器）来说，这段时间听到的是**形态武器自己的命中音**，变形武器配置的音被整体绕过 ⇒ 必须在武技入口同步过去（`KindOfWeapon` 为此加了 `setHitSound(String)`，因为 `hitSound` 是 `items` 包的 **protected**、`items.weapon.melee` 跨包写不了；对照 `augment` 是 public 才能被 `formInstance.augment = ...` 写）；③**只在「命中」分支触发**（`effectiveDamage > 0 || !enemy.blockSound(...)`），未命中走 `Assets.Sounds.MISS`；④**技能里直接 `enemy.damage(dmg, src)` 的伤害不经过 `Char.attack`，因此完全不出命中音**，要出声必须自己 `Sample.INSTANCE.play(...)`（Furioso-Replica 九连击就是这种情况）。**新增音效资源三件套**：`Assets.java` 加常量 → **必须同时塞进 `Sounds.all[]`**（漏了就是静默无声，`Sample.load` 只认这张表）→ 文件放 `core/src/main/assets/sounds/`；规格照项目惯例 **mp3 / 44100Hz / 单声道 / 64kbps / ≤2s**（长于 2s 的如 jelly 5.9s 是特例）。响度建议用 `_chk/import_lcb_sfx.py` 的量测+闭环归一：项目现有音效是**均值 −18.9~−22.6 dB、峰值 −2.5~−3.8 dB**，直接拿外部素材入库会因录制电平差出 6 dB。
- **角色语音 = 一个「每角色一个入口类」+ 六条铁律**（2026-09-18 拇指 `ValencinaSfx` / 中指 `MiddleFingerVoice` / 环指 `RingMasterVoice`）：
  入口类放**该角色技能所在包**（`actors/hero/abilities/<角色>/XxxSfx|XxxVoice.java`），把「素材、触发条件、去抖」全收在一处，调用方只写一句。
  ①**语音与头顶文本必须成对**：做成 `text + sound + duration` 三元组（`Line` 小对象或 `String[][]`），一次取用、同时播；
  拆成两张表各自随机就会出现「显示 A、念的却是 B」。
  ②**「上一条没播完就整条跳过」**：`Sound.play` 是**叠加式**的（不打断上一条），连击/连续受击时不拦就会糊成一团。
  判据 `lastAt > 0 && Game.timeTotal > lastAt && Game.timeTotal - lastAt < duration`——时间戳**必须是 `Game.timeTotal`（累计秒），
  不能用 `Game.elapsed`（每帧增量 ≈0.016s，当时间戳用差值恒为负、去抖直接失效）**；前半条件应对游戏重启（`timeTotal` 归零而静态字段仍是旧值）。
  ③**每条素材的时长要量出来写死**（`Sample` 不提供「还剩多久播完」的查询）：`ffmpeg -hide_banner -i x.mp3` 读 `Duration`，
  偏大只是多等一会儿、**偏小会叠音**。`_chk/audio_format_check.py` 报的时长是**按帧数估算**的（比解码实测大 0.07s 左右），别拿它当准。
  ④**入口类自己认人**（`Dungeon.hero.heroClass == Xxx`）：通用钩子（`Hero.damage` 的受击、`SealedSwordBase` 的解封）是所有角色共用的，
  不判职业 = 人人都说这句台词。
  ⑤**「技能演完才播」的台词挂在连段的最后一拍，不是按下按钮时**（对照 `InstantExecution.Execution` 的 `case 5`，
  与 `activate()` 里的「使用时」音效区分开）。
   **「挂在哪」的通用判据**：`Buff.affect` 的**授予处**＝「获得时」（别写进 `FlavourBuff.act()`，它整个生命周期只调一次，见 §6）；`act()`＝「回合开始时」的持续判定（账簿满充能那种）；武器/技能内部＝「使用时」。
  ⑥**语音通道与攻击音效通道必须分开**：语音的去抖窗口是 1~5 秒（上一条没播完就跳过），打击音若共用同一条通道，
  刚喊完台词的那几秒里打击音会被整段吞掉 ⇒ 入口类里另开一个**不带去抖**的播放口（`playStrike()` 之类，
  内部直接 `Sample.play( Random.element(...) )`），素材另起一组常量。语音照旧只受自己的时长约束、打击音每次命中都响。
  ⑦**条件条目**：同一张台词表里可以带「仅在某个条件下才进入候选池」的标记（环指 `Line.tibiaOnly`＝装备「一生之作-提比娅」
  才随机得到「提比娅的旋律」那两条）。判定必须在**每次触发时现算**（`hero.belongings.weapon() instanceof Xxx`），
  **不要缓存**——缓存了换武器就得等下次重新计算才生效。候选池用「遍历+筛选」建，别用 `do{随机}while(不满足)`（后者在极端情况下会死循环）。
