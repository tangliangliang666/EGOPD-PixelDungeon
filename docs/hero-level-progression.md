# 英雄 1~30 级基础数值调研（武器数值设计参考）

> 用途：为「按英雄等级切换形态」的武器做数值基准。本文所有数字均来自本仓库源码公式（`core/`），
> 不是估算；计算脚本 `_chk/hero_level_curve.py` 可复跑核对。

## 1. 一句话结论

英雄 1~30 级的基础数值**全部是线性的、且没有任何拐点**：

| 属性 | 1 级 | 30 级 | 增长方式 |
|---|---:|---:|---|
| 最大生命 HT | 20 | 165 | 每级 **+5**（线性） |
| 命中（attackSkill） | 10 | 39 | 每级 **+1**（线性） |
| 闪避（defenseSkill） | 5 | 34 | 每级 **+1**（线性） |
| 天赋点 | 0 | 29 | 按档位阶梯跳变（唯一的非线性项） |
| 力量 STR | 10 | 10（与等级无关） | 只靠力量药剂 / 戒指 / buff |
| 武器伤害、护甲减伤 | 与等级无关 | 与等级无关 | 只看装备阶数、强化、力量 |

**设计含义**：等级带来的强度差，真正的大头是「生命 ×8.25」+「29 点天赋点」，
命中/闪避只是 10→39 / 5→34 这种温和的线性差（实战命中率差异约 10~15 个百分点，见第 4 节）。
所以「1 级形态 vs 30 级形态」的强度差不能靠给命中/闪避来体现，那是杯水车薪。

## 2. 公式与源码位置

| 项目 | 公式 | 源码位置 |
|---|---|---|
| 等级上限 | `MAX_LEVEL = 30` | `Hero.java:228` |
| 最大生命 | `HT = 20 + 5*(lvl-1) + HTBoost` | `Hero.updateHT()` Hero.java:286 |
| 命中 | 初始 `10`，每次升级 `attackSkill++` | Hero.java:242 / 2380 |
| 闪避 | 初始 `5`，每次升级 `defenseSkill++` | Hero.java:243 / 2381 |
| 升级所需经验 | `5 + 5*lvl` | `Hero.maxExp()` Hero.java:2419 |
| 命中判定 | `acuRoll = U(0, attackSkill)` vs `defRoll = U(0, defenseSkill)`，`acuRoll >= defRoll` 即命中 | `Char.hit()` Char.java:810-852 |
| 等级上限之后 | 经验清零 + 给一个 `Bless` buff | Hero.java:2383-2390 |
| 力量 | 与等级完全无关 | `Hero.STR()` Hero.java:305 |

命中判定推导（`Random.Float(n)` 是 `U[0,n)`）：设攻方技能 A、守方技能 D，则

```
A >= D 时   命中率 = 1 - D/(2A)
A <  D 时   命中率 = A/(2D)
```

**只看 A/D 的比值，与绝对数值无关。** 这是后面所有命中率表的计算依据。

## 5. 与等级无关、但决定武器强度的其余三个轴（设计时需一并定）

武器/装备的强度实际上由这四个轴共同决定，等级只是其中一个：

| 轴 | 公式 | 来源 |
|---|---|---|
| 武器基础伤害 | `min = tier + lvl`；`max = 5*(tier+1) + lvl*(tier+1)` | `MeleeWeapon.min/max` MeleeWeapon.java:274-283 |
| 武器命中系数 | `ACC / 1.5^力量不足点数`；攻击延迟 `DLY * 1.2^力量不足点数` | `Weapon.accuracyFactor/baseDelay` Weapon.java:312-352 |
| 武器力量需求 | `(8 + tier*2) - ⌊(√(8*lvl+1) - 1)/2⌋` | `Weapon.STRReq` Weapon.java:389-393 |
| 护甲减伤 | `DRMax = tier*(2+lvl)`，`DRMin = lvl`（互相截断）；闪避 `÷1.5^力量不足点数 + 刻印` | `Armor.DRMax/DRMin/evasionFactor` Armor.java:379-431 |

**力量进度的硬数据**：`Dungeon.posNeeded()`（Dungeon.java:546-560）写明「每个 5 层区段 2 瓶力量药剂」，
即正常通关到 25 层共 **10 瓶**，力量 10 → 20；若把力量药剂转成精通药剂使用，
武器/护甲的力量需求各自 -2（`MeleeWeapon.masteryPotionBonus` / `Armor.masteryPotionBonus`）。
**这条与英雄等级完全解耦** —— 1 级的英雄也可能已经吃了 3 瓶力量药剂（如果开了特殊玩法），
30 级的英雄理论上也可以喝得很少。用它做武器形态判据时要小心「等级高但力量低」的合法状态。

## 6. 经验阻断的落点与副作用（供后续开发参考）

经验进账的唯一收口是 `Hero.earnExp(int exp, Class source)`（Hero.java:2315），
怪物死亡时由 `Mob.die()` 调用（Mob.java:882）。

| 落点 | 效果 | 副作用 |
|---|---|---|
| `Hero.earnExp()` 开头直接 return | 彻底不涨经验、不升级 | 同方法内的**其它收益一起被掐掉**（见下） |
| 只清 `this.exp` / 冻结升级分支 | 经验条不动，但仍触发收口内的所有 on-exp 效果 | 需要拆方法，改动更大 |

`earnExp()` 里除了加经验，还顺带做这些事（都按 `percent = exp/maxExp()` 计算）：

- 神器充能：`EtherealChains`、`HornOfPlenty`、`AlchemistsToolkit`、`MasterThievesArmband`、`Berserk`（Hero.java:2323-2336）
- 背包物品回调 `onHeroGainExp(percent, hero)`（Hero.java:2338-2341）
- 天赋计数器：`RejuvenatingStepsFurrow`、`ElementalStrikeFurrowCounter`、`HallowedGroundFurrowTracker`（Hero.java:2342-2359）
- 升级本身：`updateHT(true)`（补满增量血量）+ `attackSkill++` + `defenseSkill++`（Hero.java:2379-2381）

两点必须一并考虑：

- **1 级形态**：`Mob.die()` 里 `int exp = Dungeon.hero.lvl <= maxLvl ? EXP : 0;`（Mob.java:869），
  而 `Mob.maxLvl` 默认 = `Hero.MAX_LEVEL - 1 = 29`。所以 1 级英雄打任何怪都拿全额经验，
  「阻止获得经验」必须由武器自己拦，不能指望系统。
- **30 级形态**：英雄到 30 级后 `earnExp()` 的 `while` 会走 else 分支，把经验清 0 并给一个 `Bless` buff
  （Hero.java:2383-2390），本来就是「经验无意义」。所以 30 级形态的「阻止经验」在数值上只是**拦截祝福 buff**，
  重点应该放在形态强度本身上。
