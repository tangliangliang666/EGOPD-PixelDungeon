  - `LoveSync.act()`：找任一存活的 MeltingLove（不区分阵营），把当前英雄装备槽 / 背包里的
    `Admiration` 实例的 `charge` 同步到 `love.HP/HT`，并沿用升级逻辑

### 设计要点

- `charge` 是 Artifact 的 protected 字段，跨类（包括外层包的 buff）写不进；通过内嵌类
  `LoveSync` 实现间接访问（Java 内嵌类对外层类的私有成员可见，无论目标实例是谁）
- 跨层场景（DirectableAlly 走 `heldAllies`）：LoveSync 当前层找不到时先 no-op，等回到爱慕
  层再继续同步，不 detach，避免过渡层掉落 buff
- 粉色史莱姆只需改 `alignment` 并 `aggro(hero)`，框架 AI 下一次 act 会自然把目标切到
  英雄（之前 ALLY + WANDERING，改 ENEMY + 主动 aggro 立即仇恨）

### 2026-09-05 22:48 用户反馈兜底漏掉

用户反馈"游戏中看到的依旧是战士的选择界面图片和动作精灵图"。根因：`HeroClass.spritesheet()` 和
`splashArt()` 的 switch 是 `case WARRIOR: default: return ...`，VALENCINA 没显式 case 会
**永远走战士分支**，但编译不会报错（Java switch 不强制穷举）。

实际文件里这两个 switch 上一轮就漏了 case——摘要里我说"已加"是错的（要么 Edit 丢失、要么没生效）。

补了三处：
- `spritesheet()` → 加 `case VALENCINA: return Assets.Sprites.VALENCINA;`
- `splashArt()` → 加 `case VALENCINA: return Assets.Splashes.VALENCINA;`
- `masteryBadge()` → 加 `case VALENCINA: return MASTERY_WARRIOR;` 占位（之前漏的）
- `armorAbilities()` → 加显式 case 复述战士技能数组（之前漏了但 default 兜底本就工作正确）

教训：switch + `case WARRIOR: default:` 形式 + 新职业 = 高危陷阱；逐 switch 过一遍是底线。
已记入 MEMORY.md「新增职业兜底教训」。
