### 2. buff 描述崩溃（IllegalFormatConversionException: d != java.lang.String）
- **根因**：`dispTurns()` 返回 **String**（FlavourBuff.java:41，内部走 `Buff.dispTurns(float)` + Messages.decimalFormat），而 ignominiousheartbuff / aimheartmark 两条 desc 模板写成 `%d` → String.format 抛异常 → WndInfoBuff 崩溃，错误窗里显示字面 `20%%`（"多一个 %"）与 `%d`。
- **铁律补充**：凡 desc 模板参数是 `dispTurns()`/`dispTurns(float)`（String）→ 占位符必须 `%s`（vanilla 全如此）；只有传 int（如 wellfed/momentum 传 `visualLeft+1`/`freerunTurns`）才用 `%d`。
- 修复：zh/en 两行 `剩余回合：%d`/`Turns remaining: %d` → `%s`；`20%%~100%%` 等字面百分号转义保持不变。buff desc() 里再次核对所有 `%` 后必须为 `%` 或 `s`。

### 3. 处置闪退：攻击无 armor 的 ArmoredStatue NPE
- 崩溃点 `ArmoredStatue.defenseSkill`（armor.evasionFactor，armor==null）。armor/weapon 只在 `createWeapon()` 赋初值，`Statue.random()` 会调；但 debug 窗直接 `new ArmoredStatue()` 生成的是"半成品"雕像，任何攻击（含处置）都会炸。
- 防御性修复（Statue.java + ArmoredStatue.java 全部解引用加 null 守卫）：
  - Statue：damageRoll / attackSkill / attackDelay / canAttack / drRoll / attackProc / die 对 weapon==null 兜底（无武器按基础结算、不掉落武器）。
  - ArmoredStatue：drRoll / defenseProc / defenseSkill / die 对 armor==null 兜底（无护甲按基础闪避与减伤、不掉落护甲）。
  - 真实地牢雕像（random() 路径）必有武器护甲，行为零变化；仅 debug/异常生成个体不再炸。
