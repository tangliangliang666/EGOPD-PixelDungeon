## 追加（三）：调试窗口「只有几条横线」——真凶是 Component 构造顺序坑（又一形态）

**用户报告**：点「调试窗口」按钮，**只出现一些横线，没有正确窗口**。

**日志线索**：`desktop-debug.log` 里刷了 16 条同样的 NPE：
`ItemStatusHandler.contains:164 → ExoticPotion.reset:107 → Potion.<init>:186`，
栈顶都是 `SpdConsoleHost.icon(S:67)` / `displayName(S:46)`。

**排查分两件事**（别混）：

### ① 横线 = 真 bug，且在**同一个坑上第三次栽**
`ConsoleListView.Row` 把「挂 icon/label」写在了 `createChildren()` 里：
```java
public Row(Image icon, String text) {
    super();                                  // ← Component() 在这里就调了 createChildren()
    this.icon = icon;                         // ← 字段初始化太晚
    this.label = Fonts.create(text, 7);
}
```
`Component()` 构造函数**自己会调 `createChildren()`**，而 Java **实例字段初始化器在 `super()` 之后**才跑
⇒ `createChildren()` 里 `if (icon != null)` 挡住（此刻是 null）、`Fonts.addTo(this, null)` 是 null-safe 也跳过，
**只有 `line = Fonts.separator(...)` 是新 new 的、成功挂上** ⇒ 每行就剩一条横线。**症状完全对上。**

**排查中途还挖出第二处同类**：`WndDebugConsole.Pane.createChildren()` 里 `list = new ConsoleListView()`，
被随后的 `list = null` 初始化器**覆盖回 null** ⇒ `buildRows` 里 `list.addRow` NPE 被
`ensureBuilt` 的 catch 吞掉 ⇒ **一行都建不出来**。以及 `Tab.bg` / `Tab.hitArea` 同病
（⇒ 页签底色与命中区永不更新）。

**统一修法**：`Row` / `Pane` / `Tab` 的建子元素动作**全部搬进各自构造函数体**，`createChildren()` 留空。
已加脚本化扫描确认模块内 `createChildren()` 里**再无任何赋值**。

### ② NPE 刷屏 = 只是噪音，不是根因
`Reflection.newInstance` 内部 `catch(Exception) → Game.reportException(e) → return null`
⇒ **调用方的 try/catch 形同虚设**，堆栈照样进日志。
真因：反射加载 `ExoticPotion` 时其**静态初始化块还没执行**，`exoToReg.get(getClass())` 返 null ⇒ `equals` NPE。
**没去动 `ExoticPotion`/`ItemStatusHandler`**（那是上游正常行为）；在 `SpdConsoleHost` 加
`sampleOf()` 走 `newInstanceUnhandled` 并就地静默吞掉，构造不出来的类退化成「类名 + 无图标」。
`spawn()`（用户主动点击）保留报错。

### 关键教训：**测试断言不够，等于没测**
原 `verify_dropin_zip.py` 只断言「窗口拿到了尺寸」，**这个断言在本 bug 下照样绿**
—— 所以上一轮我把窗口"修好了"却根本没修对。本次补上真探针：
- `WndDebugConsole.debugRows()` 暴露当前页签的行
- `Row.debugChildCount(CHILD_ICON|CHILD_LABEL)` 用 **`Gizmo.parent == this`** 判「是否真被 add 进去」
  （**不能**只判「字段非空」—— 两者恰恰会背离，这正是坑的本质）
- demo 的 `icon()` 从「返回 null」改成「返回真 Image」，否则图标路径根本测不到
- 还顺手补全了 stub：`Gizmo.parent` 字段、`Group.add` 真的 reparent、`BitmapText.text()` 无参 getter
  （原 stub 缺这些，导致探针在 harness 里编不过）。

**反向验证**（很重要）：我先把 `Row` 临时改回 buggy 版，确认测试**准确 FAIL** 并打印
`only 0/1 rows attached their icon`，再换回修复版得到
`PASS: ... rows=1 all with icon+label`。**改前先证明测试能抓到它**，否则新断言可能是假绿。

**核验**：`:debug-console:compileJava` + `:core:compileJava` BUILD SUCCESSFUL；
`check_utf8_all.py` 1448 文件 OK；`check_unused_imports.py` ALL PASS；
`verify_dropin_zip.py` **4/4 PASS（含新断言）**。
新 zip：`debug-console-1.0.0.zip` 16 条目 / 38,458 字节，md5 **`c12a46a5884543885571da5564af7431`**。

## 追加（六）：调试窗「页签图标对了但名称全错 / 怪物页崩」—— 两个真根因

用户反馈：「现在可以看到页签和图标，但 UI 显示和之前的完全不同，并且绝大部分名称都没有正确匹配」。

### 根因 A（名称全错）：字体接缝定成了 `Visual`，接不了 CJK 文本控件

`SpdConsoleFonts` 原来返回 `BitmapText(PixelScene.pixelFont)`。而 `PixelScene` 用
**`BitmapText.Font.LATIN_FULL`** 加载该字体（源码注释就写 `Only latin characters supported`），
`Font.get(ch)` 缺字形落到 `get('?')` ⇒ **所有中文名整列变问号**。
名字其实一直是对的（`Messages.titleCase(name())` 与旧版逐字一致），只是**没有字形可画**。

旧版 `WndDebug` 之所以正常：它用 `ScrollingListPane.ListItem`，标签是
**`PixelScene.renderTextBlock(7)` → `RenderedTextBlock`**，走 libGDX FreeType 管线（有 CJK 字形）。

**卡点**：`RenderedTextBlock extends Component`（不是 `Visual`）。库侧 `Fonts.Provider.create`
原返回 `Visual` ⇒ **类型层面就不可能把 Component 型文本控件交回来**。

**修复**：把整条文字接缝从 `Visual` 抬到 **`Gizmo`**：
- `Fonts.Provider.create` → `Gizmo`；新增 `styleAsTitle(Gizmo)`（可选，宿主自带标题配色）。
- `Fonts.at/widthOf/heightOf/alpha/tint` 同时支持两形态；新增 `squeezeToFit`（只对纯 `Visual` 压，
  `Component` 的缩放交给它自己）。
  **`Component` 必须走 `setPos`**（直接写字段不会触发它自己的 `layout()`，文字会偏位）；
  尺寸**必须走 `width()/height()` 方法**（`Component` 用 protected 字段遮蔽了 `Visual` 的公开字段，读不到）。
- `ConsolePanel.align(Gizmo)`、`ConsoleListView.Row.label` 一并改 `Gizmo`。
- `SpdConsoleFonts` 改为 `PixelScene.renderTextBlock(size)` + `setHightlighting(false)`；
  `styleAsTitle` 里 `hardlight(Window.TITLE_COLOR)`（对齐 `ScrollingListPane.ListTitle`）。

### 根因 B（怪物页崩 / 行被静默吃掉）：`Mob.sprite()` 拿到 null `spriteClass`

`Mob.sprite()` = `Reflection.newInstance(spriteClass)`。**有些活体怪的 `spriteClass` 要到
放进关卡才赋值**（`VaultMob`/`DemonSpawner`/`FungalCore`/`IndexAgent`/`Masterpiece` 这类），
于是收到 `null`，libGDX `ClassReflection.newInstance(null)` 直接 NPE。
因为 `buildRows()` 是逐行 try/catch，**不崩窗口，只把那行静默吃掉**（列表莫名断在半途）。

旧版 `WndDebug$MobTab.build()` 正是 try/catch 兜到 `new ItemSprite(ItemSpriteSheet.MOB_HOLDER)`。
新增 `SpdConsoleHost.mobIcon(Mob)`：try `mob.sprite()` → 成功且非 null 用之，否则 `fallbackMobIcon()`。

### 外观差异（「UI 显示和之前的完全不同」）—— 已通过库设置项收敛

旧窗是 `WndTabbed`(SPD `Window`) + `ui.ScrollingListPane`；新库自带 `ConsolePanel/ConsoleListView`。
不搬回旧控件（库要跨项目可用），而是**用 `DebugConsole.settings()` 把游戏侧常量对齐**：
`rowsPerTab(2)`、`listItemHeight(18)`（= `ScrollingListPane.ITEM_HEIGHT`）、`iconBoxSize(16)`、
`labelSize(7)`、`titleLabelSize(9)`、`tabLabelSize(9)`、`tabHeight(25)`（= `WndTabbed.tabHeight()`）、
`panelBorder(false)`（宿主自绘边框）。
