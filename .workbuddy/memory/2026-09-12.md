## 追加调整（八）：加护形态修复（护盾/受击计数）+ 区间夹取规范化
- **护盾不积攒**：真凶有两层——① 结算写在**非静态内部类** `BlessingBuff.act()` 上，与「剑在转」（由
  `TearSword.act()` 的 `ensureVisual()` 驱动）不是同一条链路；② 护盾量=L、上限=3L，而神器**初始等级 0**
  （升 1 级 ≥4 次唤剑）⇒ 每回合 +0、上限 0，效果静默为空（同时 `x+L` 的护甲加成却看得到）。
  **修复**：护盾结算搬进 `TearSword.act()`（只要还有剑就必然每回合 act ⇒ 盾与剑同一生命期）；
  `shieldProgress` 存档键 `shield_progress`；`SHIELD_PERIOD/SHIELD_CAP_PER_LEVEL` 常量搬到 TearSword；
  **L=0 按 1 算**；仍要求神器装备中且未被诅咒。神器 `BlessingBuff.act()` 只剩形态同步。
- **受击不减少泪剑**：钩子原在 `Hero.damage()` 的 `if (effectiveDamage <= 0) return;` **之后**，
  于是「护甲减到 0 的挨打」和「被盾整口吃下」都不计数（攒盾反而刷不掉剑），试炼场（dmg 被置 0）更是永不计数。
  **修复**：前移到最终 dmg 算出后、`super.damage` 之前 → `if (dmg>0 && src instanceof Char && src!=this)`。
- **区间夹取规范化**：`TearSword` 上新增具名工具 `clampRaisedMin / clampMaxToMin / clampReducedMax`
  + 开关常量 `ARMOR_MIN_BONUS_RAISES_MAX`（默认 true＝抬下端时上端一并抬到同值，`+N` 足额；
  false＝下端截断在原上端，上限不动）。落点 `Hero.drRoll()` / `KindOfWeapon.damageRoll(Char)`。
- 核验：单文件 `javac` EXIT=0（未跑 Gradle）；数值验算护盾节奏、共用计数、夹取边界全通过。

  `ARTIFACT.defaultProbs` 同步追加 `1`（长度 14→15，**必须等长**）。此前池内自定义神器只有 `Admiration`。
  权重 1 ⇒ `randomArtifact()` 里 `cat.probs[i]--` ⇒ **单局最多一件**，与原版神器/爱慕一致。泪锋加护从此可从正常渠道刷出，不再只能调试窗拿。
- **版本**：`build.gradle` 921→**922**、0.2.1→**0.2.2**。
- **产物**：`android/build/outputs/apk/debug/EGOPD_0.2.2.APK`（37,142,627 B）。`aapt dump badging` 实测
  `versionCode=922` / `versionName=0.2.2-INDEV` / `applicationId=com.mypd.mypixeldungeon.indev` / minSdk21 targetSdk36。
- **含改动的证据链**：`:android:dexBuilderDebug` executed（非 UP-TO-DATE）→ `javap -c Generator$Category.class` 里
  `TearSwordBlessing` 字面量夹在 `Admiration` 与 `TimekeepersHourglass` 之间 → `core-0.2.2.jar` 内该 class 与 `build/classes` md5 一致（e0764c8f…）。
- **打包踩坑（重要）**：
  ① `JAVA_HOME` 未设 → 落到系统 JDK **1.8** → Gradle 9.4 直接拒跑（"requires JVM 17 or later"）；项目自带 JDK 21 = `D:/PD/tools/jdk-21.0.12.1+1`。
  ② 用户正在跑 `:desktop:debug`（游戏进程 + 构建守护进程）时，`executionHistory.lock` 被独占 → 其它构建报"拒绝访问"（`--no-daemon` 也无效）。
  **别用 `--project-cache-dir` 绕锁**：我试了，确实能起构建，但两个构建互踩 `android/build/intermediates`，最后倒在
  dexBuilder 写 `desugar_graph/…/graph.bin (拒绝访问。)`，白等 5 分钟。
  ③ **中断构建 ≠ 结束守护进程**：`TaskStop` 杀掉客户端后，守护进程继续跑并占住中间产物 → 恢复三步：`gradlew --stop`（若报
  "No Gradle daemons are running" 但仍有 ~1GB 的 `java.exe`，说明注册表不认识它 → 直接强杀该 PID）+ 删 `android/build/intermediates/desugar_graph` + 重打。
  删后 dexBuilder 回退非增量并打印 "Fall back to non-incremental mode"，属正常，构建 32s SUCCESSFUL。

  `docs/features.md` 追加「五、泪锋的加护入池 + 0.2.2 打包」。
