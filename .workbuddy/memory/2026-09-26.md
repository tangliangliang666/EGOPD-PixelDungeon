## 修 Bug：「打死不给经验」的怪不该吃 CHESED 回血 / GEBURA 濒死豁免

**需求（用户原文）**：矿洞任务层的小怪实际上不给予经验，因此应该没有无敌/回血，但是目前他们都有回血和无敌，请你检查后进行特殊设置。

**根因**：CHESED 的 `Trials.bindMobPassives`（回血计时器 `ChesedMend`）与 GEBURA 的
`Trials.interceptLethalDamage`（濒死豁免）原先都只判 `mob.EXP <= 0`。但「给不给经验」的**真判据**
写在 `Mob.destroy()`：`int exp = Dungeon.hero.lvl <= maxLvl ? EXP : 0;` —— 英雄最低 1 级
⇒ **`maxLvl < 1` 表示「任何英雄等级都不给经验」**。矿洞任务层三小怪（`CrystalWisp` / `GnollGuard` /
`FungalSpinner`，由 `MiningLevel.createMob()` 按 `Blacksmith.Quest.Type()` 产出）恰恰是
`EXP = 7` ＋ `maxLvl = -2` ⇒ 有正 EXP，旧判据**看不见**它们，白送 7 回合 GEBURA 豁免
＋ 每 5 回合 10% CHESED 回血。

**修法（只改 `Trials.java` 一个文件，`Mob.java` 一字不动）**

- 新增共用判据 `public static boolean grantsNoExp( Mob mob )`
  ＝ `mob.EXP <= 0 || mob.maxLvl < 1`（纯读取、无 `Random`、与英雄状态无关）。
- `bindMobPassives`：`if (mob.EXP <= 0) return;` → `if (grantsNoExp( mob )) return;`
- `interceptLethalDamage`：`Mob mob = (Mob) ch;` 之后补 `if (grantsNoExp( mob )) return false;`
- `modifyMobHT`（CHESED 的 HT +25%）**刻意不动** —— 用户只点了「无敌 / 回血」。

**爆炸半径**（被正确排除的）：矿洞三小怪；矿洞任务 Boss `CrystalGuardian` / `FungalSentry`（`maxLvl=-2`）；
`YogFist` 的拳头、`YogDzewa` 的召唤物；`RipperDemon`（`EXP=9 //for corrupting`）；
`Necromancer.NecroSkeleton`（`maxLvl=-5 //no loot or exp`）；`DwarfKing` 的召唤物。
**不受影响（刻意保留）**：`YogDzewa`(EXP=50) / `GnollGeomancer`(EXP=20) / `DM300` / `Tengu` / `Goo`
主类都没有负 `maxLvl`；普通层怪照旧。
⚠️ 顺带收益：`YogFist` 拳头 / DwarfKing 召唤物不再无敌 ⇒ **DwarfKing 二阶段屏障「打不动」的死局解开**

## 续四：四项二层天赋效果改写（变换无常 / 狩猎一餐 / 骨骸编织 / 纹身铭刻）

用户需求：① 神谕代行者 T2「变换无常」从「闪避数值 +10%/+20%」改为「比大小时闪避掷点额外重复 1/2 次取最高」；

### 一、为什么「变换无常」必须换收口点
`max(R, R')` 是**比较运算**，无法用 `R × k` 等价表达（乘区只能整体缩放同一条分布）⇒ 不是改系数，是**换收口点**：
- 把 `Char.hit()` 里内联的掷点段**原样抽成** `private static float evasionRoll(Char defender, float defStat)`，
  九条既有乘区（Bless ×1.25 / Hex ×0.8 / Daze ×0.5 / `ChampionEnemy.evasionAndAccuracyFactor` /
  `AscensionChallenge.statModifier` / BLESS 天赋 / `FerretTuft` / 沉默的代价）**一条不动地搬进去**，乘区只写一份。
- `hit()` 里改成 `float defRoll = evasionRoll(...)` 然后 `if (defender instanceof Hero)` 循环
  `rerolls = pointsInTalent(SHIFTING_FATE)` 次取 `Math.max`。
- `Hero.defenseSkill()` 的旧 `SHIFTING_FATE` 乘区分支**删除**，原地留说明注释（防后人当漏改加回去＝双重加成）。
- ⚠️ **刻意保留的边界**：`Talent.dodgeAsDamageReduction` 与 `Stone.proc` 的**闭式复刻**表达不了「取最高」⇒
  蜕变卷轴混搭时会按单次掷点估算减伤（偏保守，不崩）。已写进 `evasionRoll` 的 javadoc。
- `defStat` 仍走 `Trials.finalEvasion(...)`（`INFINITE_EVASION` 短路在前）⇒ 未连累考验 / 预知眼。

### 二、奥丁之眼缺「外部补充能」入口
`OdinsEye.charge()` 是**自动充能**专用、自带 0.25 换算率 ⇒ 直接复用会只发 0.25 点。故新增语义不同的
`public static void restoreCharge(Hero, float)`（1:1 计入）：守卫链 = null/amount≤0 → 魔免 → 装备位查找
（`artifact` 找不到找 `misc`）→ 被诅咒 → 已满，全部**静默跳过**；`partialCharge += amount` 后 `while` 进位
（支持 1.25 小数结转），封顶 `charge = chargeCap; partialCharge = 0;`，末尾 `Item.updateQuickslot()`。
`Talent.onFoodEaten` 的 `HUNTING_MEAL` 分支改调它（+1 = 1 点 / +2 = 1.25 点）。
⚠️ **同一方法里 LOYALIST T2「专注一餐」仍要充武技**（`MeleeWeapon.Charger`）。

### 三、骨骸编织：只改区间，不动结算
