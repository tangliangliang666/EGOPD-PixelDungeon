## 果冻音效音量下调（1f → 0.45f）

- 用户反馈「音效比起其他音效太大」。原因是素材是 5 秒**音乐**、录音电平高于原版短音效，而 `SFX_VOLUME=1f` 在 SPD 里就是「与其他音效齐平」。
- 改动仅一处：`JellyWobble.SFX_VOLUME` **1f → 0.45f**（≈ −6.9 dB）。
- **为什么只改这一个常量就够**：`Sample.playExclusive(id,vol,pitch,duration)` 内部就是 `play(id, vol, pitch)`，
  vol 最终乘设置音量 ⇒ 与所有原版音效同一路径，改这个值＝让它相对其他音效更轻，无需动引擎侧。
- 音量与独占时长**无关**（`duration` 仍 `SFX_SECONDS/pitch`）⇒ 改音量不会改变「BGM 被顶掉多久」。
- 可调区间：更轻 0.3 / 回响 0.7 / 齐平 1.0。
- 校验：javac 单文件 EXIT=0（**注意 classpath 必须同时含 `core/build/classes/java/main` 与 `SPD-classes/build/classes/java/main`**，只给 core 会报「找不到符号 Random / 程序包 Sample 不存在」）；`check_utf8_all.py` 1424 文件 OK。
- **未打包**：`EGOPD_0.2.5.APK` 仍是 1f 旧音量，下次打包才生效。

## 四位角色专属 BGM（设置开关 + 引擎层曲目钩子）

用户给了四首角色专属 BGM（食指/环指/中指/拇指），要求菜单里加开关、开启时替换原版 BGM。
**定案（用户选定）**：**一个总开关**，用哪首由当前英雄职业决定；**不是这四职业时不出现该选项**。

1. **素材是真 mp3**（`ffmpeg -i` 报 `Audio: mp3 (mp3float), 44100Hz, stereo`）——不是上次那种
   「MP4 装 mp3 扩展名」的假货。**统一走 mp3 而不是 ogg**：`Music` 里有「iOS 不能播 ogg ⇒ `.ogg`→`.mp3`」
   的替换，原版音乐才需要双份；自定义曲直接给 mp3 三端通吃，不用维护两份。
2. **转码**：脚本 `_chk/import_hero_bgm.py`（`--bitrate` / `--dry`），44100Hz/stereo/**96kbps**，
   **22.44 MB → 10.31 MB**。入库名 `hero_oracle / hero_ring_master / hero_middle_finger / hero_valencina`。
   放 `core/src/main/assets/music/` —— **三端 assets 都指向 core**（android sourceSets、desktop build.gradle
   的 `from project(':core')/src/main/assets`、ios robovm.xml 的 `<directory>../core/src/main/assets</directory>`），只放一处。
3. **`Music 是流式解码`**（gdx `Music` 边读边解）⇒ 文件体积只影响包体/安装占用，**不影响运行时内存**；
   对照 `Sample`（音效是整段解码进内存的）。
4. **引擎层钩子**：`com.watabou.noosa.audio.Music` 新增 `TrackOverride` 接口 + `setTrackOverride`，

   - **幂等是硬要求**：`playTracks` 命中后内部还会调 `play(forced,true)` ⇒ 钩子被再问一次，

   - **`lastPlayed` 记的是替换后的名字** ⇒ 开关来回切会正确判成换曲；同曲时 `play` 直接 return 不打断。
5. **游戏侧 `HeroBgm`**（根包）：`track()` 在「开关关 / `Dungeon.hero == null` / 职业不在四位之列」时返回 null。

- **文件 URL 规则**：`https://huiji-public.huijistatic.com/limbuscompany/uploads/<md5[0]>/<md5[0:2]>/<真实文件名>`，

## C. 地图贴图渲染调研（「两格高的草」怎么实现的）
- 结论：`assets/environment/tiles_*.png` = **256×256、16×16 帧网格、每帧 16×16px**（`DungeonTilemap` 用 `TextureFilm(tex,16,16)`）；`Tilemap.updateVertices()` 把第 (col,row) 帧铺在 `(col*16,row*16)`，**帧永不越格** ⇒ 「比一格高」的视觉只能靠**相邻两格各画半截**拼。
- **三个同 map 的 tilemap 分工 + z 序**：`DungeonTerrainTilemap`（terrain 组，角色**之下**：地面/抬高地形本体/墙正面）、`RaisedTerrainTilemap`（角色**之上**：抬高地形"下悬"）、`DungeonWallsTilemap`（角色**之上**：墙内部黑块 + **上一格**的檐）。`DungeonTileSheet` 分行：1-3 地面/水/深渊、4-5 FLAT_*（仅 examine 小图）、6-9 RAISED_*、10-12 WALL_INTERNAL_*（全黑）、13-14 WALL_OVERHANG_*、15-16 OVERHANG/UNDERHANG。
- **高草 = ①拆帧 ②跨格 ③z 错位**：草丛约 19px 高被切成 `HIGH_GRASS_UNDERHANG`（只画第 0~10 行，画在草格自己）+ `HIGH_GRASS_OVERHANG`（只画第 8~15 行，画在**上面那一格**，由 walls 层判 `map[pos+mapWidth]==HIGH_GRASS` 得到）⇒ 连成一条草叶带、顶到上一格中部；草皮 `RAISED_HIGH_GRASS` 在角色之下、草叶在角色之上 ⇒ 遮挡纵深。
- **实测遮挡**（把角色画成品红逐像素判定）：站**草格上方那格** → sprite 第 8~15 行（腿）被草盖；站**草格本体** → 第 0~10 行（头/身）被盖、第 11~15 行（脚）露出；站**草格下方那格** → 完全不受影响。
- 抬高格坐标用 `raisedTileCenterToWorld`（中心 y 从 `(行+0.5)*SIZE` → `(行+0.1)*SIZE`，上移 0.4 格）；水不走 tilemap（`needsRender` 跳过纯 WATER 帧，水体是 `SkinnedBlock`）；`WallBlockingTilemap`(4 帧) 画墙旁阴影；`tileVariance[]` 按 `seedCurDepth()` 决定 ALT 帧。

- 根因不是「坏了」而是**一直缺**：原版命中音全挂在 `hero.attack(...)` 返回 true 的分支里，而**踏碎不走 `hero.attack`**（直接 `Hero.heroDamageIntRange → enemy.damage`，无命中判定、必中）⇒ 从来没人播过。
- **可复用判据**：给技能接音效时**先问「这一下走不走 `hero.attack`」**，不走的一律自己补播放口。

### B. 素材：`middlefather_0_1 / _0_3 / _0_5.ogg` → `middlefinger_strike_1/2/3.mp3`
- **「第 1、2、5 条」= 表格列表位置**，不是文件名数字：技能0 组 11 个文件编号有跳跃（`_1 / _3 / _4-1 / _4-2 / _5 / _6 / _7-1 / _7-2 / _8 / _9-1 / _9-2`，**没有 `_0_2`**）。
- 源素材 48kHz 立体声 vorbis，**真峰值全是正的**（+0.59/+0.98/+1.40 dBTP）⇒ 增益为负（−5.00/−4.30/−3.30dB）；走**音效档** `--target-mean -20`（语音档是 −15）。入库 44100/mono/64k，LUFS 散布 2.41dB、真峰值全 <0。
- 入库解码时长 1.9294 / 1.5124 / 1.4104 s。

### C. 落点：五式统一 `MiddleFingerVoice.playStrike()`
- `doStomp`（**新增**，放在伤害掷值之后）／`doKick` 的 strike 回调／`doPierce` 逐目标循环／`doRestomp` 每段循环／`doExecution` 三段循环，5 处全部取代原版 `HIT_STRONG`。
- `VengeanceArts` 因此**不再用 `Assets` / `Sample` ⇒ 两个 import 已删**（留着会让人以为还在播原版音效）。

### D. ⚠️ 关键设计：打击音**分通道**，不走语音去抖
- `playStrike()` 内部**没有 `busy()` 检查**。语音去抖窗口 1~5 秒，而复仇技艺是「喊台词 + 同时打出去」⇒ 共用通道的话**刚喊完「给我过来！」的几秒里打击音全被吞掉**，等于白接。
- 归一化到规范：**同一个角色入口类可以有两条独立通道**（语音带去抖 / 音效不带），素材也分两组常量 → 写进 AGENTS.md §4 ⑥。

## F. APK 图标不生效 + 应用名改 EGOPD（承接 E）

**症状**：用户已把 launcher 图标重画成红黑黄（`ic_launcher.png` 192×192 主色 `#151515/#B3001E/#FFFFFF/#DD9800`，HEAD 版是 `#DD9800/#0A3D0A` 金绿），但打包安装后仍是原版金绿；名称想从 `My Pixel Dungeon` 改 `EGOPD` 但怕丢存档。

**根因（已用 aapt 铁证）**：`AndroidManifest` 的 `android:icon="@mipmap/ic_launcher"` 在 **API 26+ 只解析 `res/mipmap-anydpi-v26/ic_launcher.xml`**（自适应图标 = `_background` + `_foreground` + `_monochrome`），`mipmap-*/ic_launcher.png` 那套扁平图**只在 API < 26 被读**。实测 `aapt dump badging` 的 `application-icon-120/160/240/320/480/640` **六档全部指向同一个 anydpi-v26 xml**。用户的 432×432 `ic_launcher_foreground.png` 与 HEAD 版 **md5 完全相同**（`51d21390b9`）= 从未改过，调色板 10 色仍是 `#DD9800/#0A3D0A/...` 原版金绿；`_background.png` 同样未改（`50ed0e8d58`，深灰石砖 `#53524E`）。而 APK 内资源尺寸与源文件逐一吻合 ⇒ 构建链本身没问题。
- **副发现**：`android/src/debug/res/` 是 `main` 的**整套重复**（upstream 本有 INDEV 专属图标，此处已同步成一样）且覆盖 main ⇒ 任何图标改动必须做 **2 套 × 4 种 × 5 档**（+2 个 ldpi 扁平图）。

**几何反推（关键方法）**：扁平图与自适应前景出自同一套像素画。逐像素 diff「HEAD 版扁平图」vs「工作区扁平图」即得几何：
```
legacy 精灵 bbox (12,12)-(179,173) 168x162      fg 精灵 bbox (104,104)-(327,319) 224x216
缩放 0.750000 / 0.750000     偏移 (-66, -66)      各调色板色像素数严格成 16:9
```
- **必须「按位置」搬运，不能按颜色全局换**：`#DD9800` 金**分裂**成 `#B3001E` 红(6264px) + 保持金(2376px) —— 外框染红但**钥匙孔牌面仍留金色**；`#0E4F0E` 也裂成 `#1C1C1C`(67%)/`#272727`(33%)。按颜色映射会把钥匙孔一并染红。
- 映射全表：`#0A3D0A→#151515`、`#0E4F0E→#1C1C1C`、`#136C13→#272727`、`#1B9C1B→#393939`（绿阶→灰黑阶）、`#DD9800→#B3001E`、`#A77400→#80263C`、`#FFEB7B→#FF002A`（金阶→红阶）；`#FFFFFF` 与 `#291E00` 不变。
- **交叉验证**：xxhdpi(324) 前景变色 **19368 px** 与 legacy(192) 的变色数 **完全相同**（432×0.75=324、224×0.75=168）⇒ 逐像素吻合。脚本 `--apply` 幂等，重跑报「换色 0 px」。

**改名与存档（结论：移动端安全，桌面端已解耦）**：
- Android 存档按 **`applicationId`** 定位：`AndroidBackupHandler` 用 `getFilesDir()`，偏好文件名**硬编码** `"ShatteredPixelDungeon"`，与 `appName` 全无关系 ⇒ 改 `appName` 不动移动端存档；**改 `appPackageName` 才是灾难**。debug 变体带 `applicationIdSuffix ".indev"` ⇒ debug/release 是**两个独立 App、两套独立存档**（易误判成丢档）。
