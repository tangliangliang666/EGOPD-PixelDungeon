## （补9）修复：泪锋之剑「绝望」形态协同突刺击杀 boss 后 boss 层不解锁

- **现象**：绝望形态下近战挥击当场打死 boss → 泪剑协同突刺对**尸体**再调一次 `damage()`
  → 走 boss 覆写（`Goo.damage()` 首行 `if (!BossHealthBar.isAssigned()) { assignBoss(this); Dungeon.level.seal(); }`）
  → 把刚解锁的楼层重新 seal 回去，出口打不开。
- **根因（认知修正，最重要）**：`Char.damage()` 开头的 `if (!isAlive() || dmg < 0) return;` **只保护基类**。
  boss 覆写 `damage()` 时首行就 assignBoss/seal，`super.damage()` 里的守卫来得太晚 ⇒
  原代码注释「Char.damage 自带 !isAlive 兜底」是**错误前提**；判定必须做在**调用方**。
- **修复**：`actors/buffs/TearSword.java` → `strikeAt()`：
  `if (dmg > 0 && target.isAlive()) target.damage( dmg, new MagicStrike() );`
  （`strikeAt` 由 `Hero.onAttackComplete` 在 `attack()` **之后**调用，主伤害可能已击杀目标——这个顺序是设计使然，不能改，只能加守卫。）
  - **刻意不动**：① 突刺动画（纯视觉、坐标当帧取样）、③ `countDecay()` 减层计数（语义「剑刺出去了就算一次」，
    与"被魔法免疫挡下也计数"一致）。二者修复前本来就会执行 ⇒ **非 boss 情形零行为变化**。
- **同类审计**：自定义代码里「同一流程多处 `.damage(`」只剩两处——`SealedSwordBase.proc`（附带火焰伤害已带
  `!defender.isAlive()` 守卫，且结算在主伤害之前）与 `DimDusk`（薄暝，早修）。本次为最后一处遗漏。
  - 附带结论：实测 `actors/mobs` 下 **30 个**类覆写 `damage()` 且覆写体内完全没有 `isAlive()`，含
    Goo/Tengu/DM300/DwarfKing/YogDzewa/CrystalSpire/Masterpiece（自定义）/RingfingerAutomaton（自定义）等 boss，
    也含 `Mob` 基类与全部 NPC ⇒ 任何新增「附加/追加伤害」都必须自己判存活。
- **核验**：单文件 `javac -nowarn -proc:none -encoding UTF-8` **EXIT=0**；文件 UTF-8 可解码（34110 B）、无 GBK 污染。未代跑 Gradle。
- **文档**：`AGENTS.md` §6 该条目重写（判定在调用方：打之前判一次 + 每段之后各判一次 + 覆写清单）；`docs/features.md` 追加本节。

## （补10）审计：火焰附加伤害的「判死」守卫（用户提问）

用户问：火焰附加伤害（含焦炭松脂）有没有在造成伤害前判目标已死？担心附加击杀 boss 时对尸体重复致伤 ⇒ 楼层不解锁。

### 结论：我们自己的两处都判了，链路端到端无洞
- `SealedSwordBase.proc` **入口一次性**判 `!defender.isAlive()` 早退（覆盖火焰伤害 / 命中特效 / 点燃三段）；且结算在主伤害之前。
- `ResinCoatingBuff.bonusDamage`：`bonus > 0 && defender.isAlive()`；调用方 `Weapon.proc` 涂层分支另有**双重** `defender.isAlive()`（`enchant().proc` 前后各一次）⇒ 恰好落实补9的「每段之后各判一次」。
- 链条顺序：`super.proc()`（附魔 → 松脂附加元素伤害）先跑，再跑剑的火焰伤害 ⇒ 前一段若击杀，后一段被自己的守卫挡下。✅

### 关键认知（再次确认，勿忘）
- **`Char.damage` 首行 `if (!isAlive() || dmg < 0) return;` 对 boss 覆写无效**（覆写体副作用早于 `super.damage`）⇒ 判定必须在调用方。原版 **`Blazing.proc` 自身未判**（`defender.damage(burnDamage, this)` 无守卫），仅因调用方 `Weapon.proc` 的 `if (defender.isAlive() && !becameAlly)` 而实际不可达；作为武器自身附魔时那一刻目标必然活着 ⇒ **保持原版未动**。
- 全工程 `Dungeon.level.seal()` 只有 **`Goo`** 会调（`Goo.damage()` 第 265 行首行 `if (!BossHealthBar.isAssigned()) { assignBoss(this); seal(); }`，另 135/316 两处）⇒「附加伤害杀死 boss 后楼层重新上锁」这个具体故障**只可能发生在 Goo（第 5 层）**；另 3 个 boss 的 `damage()` 覆写不重新上锁。
- 9 个覆写 `isAlive()` 的相位单位（Hero-Berserk / Tengu / YogDzewa / DwarfKing / DM300 / Brute / Ghoul / CrystalGuardian / GnollGeomancer）：HP=0 时 `isAlive()` 仍 true ⇒ 附加伤害会继续打上去，但这是**设计如此**（`die()` 由相位逻辑显式调用一次，不会重复）。**Goo 不在其中**（它只覆写 `damage()`）⇒ Goo 死后守卫有效。

### 顺带查出的真缺口（未擅自改，待用户定夺）
**松脂涂层击杀不计入「英雄击杀」**：`ResinCoatingBuff.bonusDamage` 用 `this`（buff 实例）当 src，而 `Mob.die` 白名单只认 `Dungeon.hero` / `Weapon` / `Weapon.Enchantment` / `Electricity` / `DimDusk.*` / `TearSword.*` ⇒ 最后一击由松脂打出时静默丢失：`RevengeLedger.onEnemyKilled`（**账簿击杀充能**）、`Instruction.onEnemyKilled`/`onBossKilled`、`RingMasterLoot` / `SmilingBlade` / `TinyGalaxy`、致命节奏 / 致命急速天赋触发。EXP 不受影响（`Mob.destroy` 里无条件给）。封印之剑的火焰伤害 src 是武器 ⇒ `instanceof Weapon` ✓ 正常计数。原版 `HolyWeapon.INSTANCE` / `Smite.INSTANCE` 同病。
- 修法二选一：①`Mob.die` 白名单加 `|| cause instanceof ResinCoatingBuff`（与 DimDusk/TearSword 同款，**推荐**，保留火属性免疫/抗性判定）；②把 src 换成武器（会丢掉 `isImmune(火焰类)` 的元素免疫语义，不推荐）。

## （补10）神器售卖设置核查：泪锋的加护 / 爱慕

- **定位**：`Shopkeeper.canSell` 第 2 行 `if (item.unique && !item.stackable) return false;` 是第一道闸。
  - `TearSwordBlessing` 初始化块设了 `unique = true` ⇒ **不可售**；
  - `Admiration` 未设 `unique` ⇒ 默认可售（唯一障碍是它初始 `cursed = true`，装备中卖不了，需先解咒卸下）。
  - 全工程神器 `unique=true` 的仅 6 个：CloakOfShadows / HolyTome / OdinsEye / RevengeLedger /
    InstructionTerminal / TearSwordBlessing —— 前五个是本作认定的「专属神器」。
- **`unique` 一标三用的坑（本次核心认知）**：除 `canSell` 外，
  ② `ScrollOfTransmutation.usableOnItem` 里 `return !item.unique;` 拿它**禁嬗变**；
  ③ `Thief.steal` / `CrystalMimic.steal` 拿 `!unique` 判**可偷/可吃**（水晶拟态会真吞物品，永久损失）。
  ⇒ **要放开出售，绝不能顺手删 `unique`**，否则神器变成可被嬗变重掷、被拟态吃掉的普通物品。
- **改法**：`Item.java` 新增 `public boolean sellable() { return !unique || stackable; }`（默认与原判定等价，
  零行为变化）；`Shopkeeper.canSell` 改调 `item.sellable()`；两神器各自 `@Override sellable() → true`。
  `Alchemize` 的炼金窗口复用 `canSell`，故其出售入口一并放开。
  `canSell` 其余三道（value<=0 / 封印护甲 / 已装备且被诅咒）不受影响。
- **核验**：4 文件 `javac -nowarn -proc:none -encoding UTF-8` EXIT=0；`javap -c` 确认 `canSell` 已
  `invokevirtual Item.sellable:()Z`、不再 `getfield Item.unique`；两神器类均含 `public boolean sellable()`。
- 文档：`AGENTS.md` §6 陷阱表在「指令终端被换下/嬗变」后补一行（unique 一标三用 + sellable() 钩子）；
  `docs/features.md` 追加「六、神器售卖设置」。

    修法待定：照 `ArtifactRecharge` 排除 `HornOfPlenty.hornRecharge` 的范式，或给 `ArtifactBuff` 加
    `acceptsRecharge()` 谓词、`Rancor` 覆写 false。

    接入系数要按此定：0.1 ≈ 一次 30 回合 buff 换 3 点（推荐）/ 0.2~0.25 = 一次直接灌满。
  - **爱慕**：❌ 未覆写 ⇒ 无效，且**不能直接接**：召唤后 `charge` 被 `LoveSync` 复用为「溶解之爱血量%」
    （每回合写 `adm.charge = hpPct`）；另注意它初始 `cursed`，而 `ArtifactRecharge` 会整段跳过被诅咒神器。

## （补12）新 buff「残像纠缠」+ 配套测试道具

## 补 17 —— 果冻摆动「上下颠倒」修复 + 幅度 6→16

1. **根因（务必记住）**：`JellyDraw` 里 UV 的 v 用 `t`（**从脚底起算**的高度比例）直接插值，
   而局部坐标 y 是**从顶边起算**（`y=0 ↔ frame.top`，见 `Image.updateVertices()`/`updateFrame()`），
   两者差一个 `1-t` ⇒ 顶边被贴上 `frame.bottom` ⇒ **整张图垂直翻转**。
   修法：`vTop`/`vBot`（各自含 `flipVertical` 互换）＋ `lerp(vTop, vBot, 1-t)`。

## 补 18 —— 果冻摆动三次调整：次数 ↑、竖直形变、死亡动画

1. **次数**：`JellyWobble.DURATION` 0.9→**1.4f**、`FREQ` 8→**14f** ⇒ 来回次数
   `DURATION×FREQ/(2π)` 由 1.15 次升到 **≈3.1 次**。**判据公式写进注释与文档了**，以后调次数只动这两个。
2. **竖直形变（关键：三路形变共用同一个「零点在底边」的锚）**：
   - `Image` 新增 `jellySquashAmp` / `jellySquash()`；`jellyWobble(amp, squash, dir, duration, freq)` 签名已改。
   - `jellySquash()` 用 **−sin(ωt)**（与横向的 cos 差 1/4 周期）⇒ 先甩出去、随后一压一弹；
     若用同一个 cos 就只是整体缩放（呼吸感），不是果冻。
   - `JellyDraw`：`vk = 1+squash`，`y = h·(1 − t·vk)`（t=0 ⇒ y=h，脚底恒不动）；
     压扁量按 t 折算横向鼓出 `halfW = w/2·(1 − squash·BULGE·t)`（`BULGE=0.6`，近似保体积）。
     **一个 quad 仍是矩形 ⇒ 整层取同一个 halfW**，相邻层宽度差 ≈ `2w·bulge/SLICES`（20 层时 <0.2px，看不出台阶）。
   - `JellyWobble.SQUASH = 0.3f`（±30%），死亡随 `DEATH_BOOST = 1.3f` 放大。
3. **死亡动画**：钩在 **`Char.die()`** 里 `sprite.die()` **之前**（`destroy()` 之后、`if (src != Chasm.class)` 块内）。
   - `Char.die()` 是**全工程唯一的死亡汇聚点**：`actors/` 下只有 `Hero` 覆写 `die(Object)`，且无复活手段时仍 `super.die(cause)`
     ⇒ 一处接线覆盖所有单位（含英雄）。**别去 28 个 `XxxSprite.die()` 里加**（大半会 super.die ⇒ 重复触发）。
   - 方向沿用 `dirFrom(target, src)`＝致命一击来向，死亡摆动会接在受击摆动后同向甩出去。
   - **必须在 `sprite.die()` 之前**：部分死亡动画会 `killAndErase()` 摘掉精灵。
4. **校验**：SPD（Image+JellyDraw）与 core（JellyWobble+Char）两次 `javac @argfile` **EXIT=0**。
   全仓 `jellyWobble(` 调用点只有 `JellyWobble.swing` 一处，签名变更无遗漏。
5. **文档**：features.md 该节新增「## 5. 修订二」；AGENTS.md §4/§6 同步。**版本号未动、未打包**。
