## A. 27 层草地变「五区蘑菇形」修复（草叶细节区域与楼层贴图对齐）

**现象**：`LobTestLevel`（27 层）已换 `tiles_lob.png`（草地材质取自第二区/监狱），但草地上叠的**草叶细节**
却是第五区/恶魔大厅的**蘑菇形**。

**根因**：草由两张图叠加 —— 草皮本体来自本层 `tilesTex()`，**草叶细节来自全局唯一的
`environment/terrain_features.png`**（256×128；每 16 帧槽一组 = 一个区域，槽 9/11/13 + 16×stage 依次
HIGH_GRASS/FURROWED/GRASS）。选段逻辑原本**只认 `Dungeon.depth`**：

```java
int stage = (Dungeon.depth-1)/5;   // 27 → 5
stage = Math.min(stage, 4);        // 夹成 4 = 恶魔大厅 ⇒ 蘑菇形
```

即 **深度 >25 的关卡一律被夹到第五区**。这是能力边界，不是图片配错。

**取证**：
- `_chk/grass_zone_mismatch.py`：terrain_features 五段主色对照 ⇒ stage 4 槽 73 = `#994C00/#8C2F00/#A68521`
  （暖褐蘑菇色），stage 1（监狱）槽 25 = `#67933D/#7A924C/#6A723D`（草绿）。
- `_chk/verify_lob_grass_stage.py`：`tiles_lob[250]` 与 `tiles_prison[250]` 的不透明像素集合完全相同、
  RGB 逐像素全等（63 个实心像素）⇒ tiles_lob 草叶确实是第二区那套（用户描述属实）；槽 122 全帧差异
  **只在底色**（lob 换暖褐底），草形同源。

**修法（通用机制，不硬编码 27）**：
- `tiles/TerrainFeaturesTilemap.java`：新增公开接口 `FeaturesTexProvider { int featuresStage(); }`，
  抽出静态 `featuresStage()` —— 实现接口则用其报值（再 `(int)GameMath.gate(0,x,4)` 夹一次），
  否则**原样走原版**（`(depth-1)/5` + 21 层商店退档 + `min(...,4)`）。`getTileVisual` 里 3 行内联 → 1 行调用。
- `levels/LobTestLevel.java`：`implements TestLevel, TerrainFeaturesTilemap.FeaturesTexProvider`，
  `featuresStage()` 返回 `(GEN_DEPTH - 1) / 5` ⇒ **跟着 GEN_DEPTH 自动走**（GEN_DEPTH=4 ⇒ stage 0；
  将来调成 7 自动变 stage 1）。

**坑**：`GameMath.gate` 返回 **float**，必须显式 `(int)` 转型，否则 javac 报
「不兼容的类型: 从float转换到int可能会有损失」。

**回归验证**：原版所有深度映射逐一比对无变化（1~5→0、6~10→1、11~15→2、16~20→3、21 商店→3、21~26→4）；
`level == null`（`JournalScene` 里重建纹理）走原版分支、`instanceof` 对 null 恒 false ⇒ 无 NPE。
修复后 27 层槽位：HIGH_GRASS 73→9、FURROWED 75→11、GRASS 77→13。

**源码级核验**：单文件 javac EXIT=0（`LobTestLevel.java` 0 行告警；`TerrainFeaturesTilemap.java` 仅余 1 条
`[this-escape]`，落在构造函数 `instance = this;` —— `git diff -U0` 确认该行不在任何 hunk 内，上游既有写法）；
括号配平 25/25 与 49/49；`check_utf8_all.py` 1432 文件全通过。**未代跑编译**（用户约定）。

## B. 地形编辑器（可视化画房间 → 生成可编译的 paint()）

**需求**：用户要做新层级开发，想要「直观编辑特定房间地形 → 输出可应用于地形生成的代码」。

**成品**：`tools/terrain-editor/`（双击 `index.html` 即用，无服务器、无外部依赖 —— 图集 base64 内联）。

| 文件 | 职责 |
|---|---|
| `index.html` | UI 骨架（顶栏 / 左工具栏 / 中画布 / 右检查+代码） |
| `app.js` | UI 装配：画布交互、工具切换、检查器渲染、撤销、导入导出 |
| `editor.js` | 编辑内核：Int32Array 网格、撤销栈、7 种工具算法、宏命令、**不变量检查器** |
| `render.js` | **手抄** Java 的 4 层渲染引擎（帧号与 `DungeonTileSheet` 对齐） |
| `codegen.js` | Java 生成器：骨架两步 + 外圈非墙逐格 + **内圈矩形合并** + 门类型循环 |
| `assets.js` | 生成物（`_chk/terrain_editor_assets.py` 产出，216,713 B），勿手改 |

**画布渲染 = 游戏真实时样子**：App 里叠的是 4 个 tilemap 层的 z 序，所以墙面自动缝合、草叶跨格拼接、
水/深渊边缘过渡都在。两个下拉框要分清：**图集**（`tilesTex()`，6 张含 `tiles_lob`）影响生成的代码；
**草叶区 0–4**（`terrain_features.png`，全局唯一）**只影响预览** —— 正是当天 A 部分那个 bug 的手工版。

**代码生成的关键决策**：
- **矩形合并**而非逐格 `set`：贪心整行扫描（先向右扩到行尾，再整行向下扩）⇒ 12×12 复杂房间只出
  **17 条语句**（6 fill + 11 set），不合并会逼近 196 条。
- 坐标直译 `left + x` / `top + y`（`Room extends Rect`，`left/top` 是 `RegularPainter` 分配的矩形，
  `paint()` 内只能用相对偏移）。
- 用 `Painter.fill(level,l,t,w,h,v)` 的**宽高重载**而非 `l,t,r,b` 重载 —— 宽高从画布直接得来，
  省掉一次 ±1 换算（`Rect` 的 **right/bottom 是闭区间**是上游最常踩的坑）。
- 骨架两条固定写死：`fill(this, WALL)` + `fill(this, 1, EMPTY)`（`StandardRoom.paint` 没有基类实现，
  每个子类都得自己写这两步）。

**内建护栏**（不是纯画图板）：每次改动重算 4 类 ⚠ + 2 类 ℹ ——
外圈破损 / **门不在外圈**（`placeDoors` 只在外圈找门位）/ 可通行格孤岛 / 全深渊 / 贴墙高草 / 无门。

## 地形编辑器：陷阱/植物覆盖层 + 水体预览修复（第二轮）

用户要求：① 加陷阱和植物的**编辑 UI**；② 同步修复**水体预览**（原来显示得和深渊一样）；
③ 随后继续实现。

### 一、核心机制发现（都写进 AGENTS.md 陷阱表了）

1. **陷阱不是地形。** `Terrain.TRAP` 只是占位符；真正存在的是 `Level.traps`（与 `map[]`
   **平行**的 `SparseArray<Trap>`）。`TerrainFeaturesTilemap.getTileVisual()` 顺序：
   ① `traps.get(pos)` → ② `plants.get(pos)` → ③ 才轮到草。
   ⇒ 生成代码必须 `level.setTrap( new XxxTrap(), pos )`；植物
   `level.plant( new Xxx.Seed(), pos )`（入参是 `Seed`，写成 `new Sungrass()` 编译错）。
   帧号：陷阱 `color + shape*16`（RED=0…BLACK=8 × DOTS=0…LARGE_DOT=6）；植物 `image + 7*16`。
   `visible=false` ⇒ 渲染返 -1、地形 SECRET_TRAP；`active=false` ⇒ 用 BLACK 色。
   **继承陷阱**：`TenguDartTrap extends PoisonDartTrap`、`GnollRockfallTrap extends RockfallTrap`
   —— 颜色/形状来自父类，核验脚本解析源码时必须上溯继承。
2. **水不走 tilemap。** `DungeonTerrainTilemap.needsRender()` 跳过纯 WATER 帧（水是
   `GameScene` 里的 `SkinnedBlock`，5 帧 water0..water4、每帧 **32×32 = 2×2 格**、平铺全图）。
   编辑器只抄了「跳过」没抄「垫底」⇒ 水格漏黑背景 ⇒ **看起来和深渊一模一样**（这就是用户的 bug）。
   修法：先铺 layer 0 水层；地形 pass 里水格只在 `wv === F.WATER`（缝合位 `r===0`）时跳过，
   **缝合边缘帧照画**（否则岸线缺一圈）。缝合位：上+1/右+2/下+4/左+8。
3. **房间不旋转也不镜像**（回答用户提问）：`RegularPainter.paint()` 只做 `shift(-leftMost,-topMost)`，
   `levels/` 下 grep `rotate|mirror|flip|transpose` **零命中**。
   但 `Room.setSize` 内部 `NormalIntRange(minW,maxW)-1` —— 宽高**各自独立**、**正态分布**；
   `SizeCategory`：NORMAL(4,10,1)/LARGE(10,14,2)/GIANT(14,18,3)，`sizeCatProbs()` 默认 {1,0,0}。
   ⇒ 写死尺寸会在尺寸变化的房间上错位。

### 四、踩到的坑（都已固化进脚本注释）

1. **DOM 桩 `dispatch` 必须 `f.call(el, ev)`** —— `app.js` 回调普遍写 `this.checked`，
   直接 `f(ev)` 让 `this` 变 undefined，报 `Cannot read properties of undefined (reading 'checked')`。
2. **`Image` 桩的 `onload` 必须同步触发** —— `boot()` 是同步跑完的，桩里用 `setTimeout`
   永远等不到图集 ⇒ `S.sheet` 为 null ⇒ `Cannot read properties of null (reading 'draw')`。
   同时桩要给 **带像素缓冲的假 canvas**（`render.js` 的 `Sheet()` 用 `getImageData` 读像素）。
3. **跨 realm 注入**：从父页 `d.createElement('script')` 塞进 iframe **有时不执行** ⇒
   改用 `iframe.contentWindow.eval(src)`。
4. **注入时机**：`index.html` 有 5 个 `<script src>`，`--dump-dom` 在脚本跑完前快照 ⇒
   必须轮询 `typeof TE_EDITOR === 'object'` 再注入，否则得到满屏「UI 没绑上」的**假失败**（实际踩了两次）。
5. **`#codeBox` 是 `<textarea>`** ⇒ 内容在 `.value`，读 `.textContent` 永远空。
6. **Windows 上 javac 的中文诊断是 GBK** ⇒ Node 按 UTF-8 解出 `�����ݵ�����`，中文关键词断言必失手。
   解法：`spawnSync` 不设 `encoding`、拿 Buffer 后 `TextDecoder('gbk')` 解码。
   另：javac 的「错误:」与正文**不在同一行**，断言要在**全文**里找。
7. **`cellFromEvent` 用 `(clientX - rect.left) / (ZOOM * 16)`** ⇒ ZOOM=2 时一格 32px；

## 地形编辑器：道具生成层（第三轮，C.4）

用户需求（原话）：「希望扩展使得加入道具生成，以及生成位置的功能，但不用渲染道具图片，
直接统一使用口粮作为图片占位」。

### 一、核心机制发现（**与前两轮不同，物品的机制完全独立**）

1. **物品根本不在 `map[]` 里。** 它们存在 `Level.heaps`（`SparseArray<Heap>`），
   `Heap` 自带 `ItemSprite`、挂进 `GameScene` 的 **objects 组** ⇒
   **地图格本身仍是普通地板**。所以画道具**不改变地形**，同一格可以既是草地又是宝箱。
   这与陷阱/植物（要写成 `TRAP` 系地形）**恰好相反** —— 检查器判据也因此倒过来写。
2. **定点投放只有 `Level.drop( Item, int cell )`。** 字节码确认
   `Level.drop:(L…items/Item;I)L…items/Heap;` ⇒ 返回 `Heap`，可链式
   `level.drop(...).type = Heap.Type.CHEST`。
   **`addItemToSpawn(Item)` 是错的**：只把物品推进 `itemsToSpawn`，
   随后 `RegularLevel.createItems()` 通过 `randomDropCell()` 消费 ⇒ **落点随机**，
   而且**编译完全能过**（纯静默错误，差一点就写进生成器了）。
   上游先例证明 `paint()` 里可以 `drop`：`RingRoom.placeCenterDetail`、`MassGraveRoom`、
   `RatChestChasmRoom`、`RatKingRoom`。
3. **口粮占位帧号 437 是算出来的**：`SIZE=16`、`TX_WIDTH=256` ⇒ `WIDTH=16`；
   `xy(x,y){x-=1;y-=1;return x+WIDTH*y;}` ⇒ `FOOD=xy(1,28)=432`、`RATION=FOOD+5=**437**`
   （col 5 / row 27 / 像素 `(80,432)`，实测 164 个不透明像素）。
   `items.png` 在 `core/src/main/assets/sprites/`（**不在** `environment/`），
   与地形图集是**两张独立的图**，编辑器单独作 `S.itemSheet` 加载。
4. **真名是 `Food` 不是 `Ration`**：`items/food/Food.java`，`public class Food extends Item`，
   `image = ItemSpriteSheet.RATION`。**类名与贴图常量是两回事** ——
   我最初的测试和 `boot()` 示范都写了不存在的 `Ration`，改正后表为 71 项。

### 二、⚠️ 本轮最重要的发现：`render()` 缺空值保护 ⇒ 首帧必崩（**会砸到每一个用户**）

`app.js` 的 `boot()` **同步**跑到底：`fullRefresh() → draw() → R.render()`；
而图集是 `new Image(); im.onload = ...` **异步**加载 ⇒ **首帧必定早于 `setSheets()`**。

原来 `render()` 无保护 ⇒ `S.sheet.draw()` 抛
`TypeError: Cannot read properties of null (reading 'draw')` ⇒ **整个 `boot()` 中断**：
所有下拉框空白、画布停在 16×16、代码框全空。

**以前没炸纯属运气**（图集加载够快）。C.4 把 `items.png` 内联进 `assets.js`
（216,713 B → 332,095 B）后**时序一变就必炸** —— 也可以说这 bug 一直存在，只是被加载速度掩盖了。

**修法**：`render()` 在 `ctx.scale` 之后直接 `if (!S.sheet) return;`；
features pass 的判据从 `if (showFeatures)` 收紧成 `if (showFeatures && S.features)`。
⇒ 行为**与加载速度无关**。

> **教训（已进 AGENTS.md 陷阱表）**：任何「资源加载完之后画面才对」的实现都是脆的，
> 首帧必须能在资源缺失时安全返回。**别用 `setTimeout`/轮询去兜** —— 那只是把竞态藏起来。

### 五、本轮踩到的坑（写进脚本注释了）

1. **`R.ITEMS` 在探针里 `undefined`** —— `render.js` 用 `global.TE_RENDER = API`，

3. **`Sheet.prototype.draw()` 对任何合法索引都返回 `true`**（哪怕全透明）⇒

5. **注入 `<head>` 用 `replace('<head>', ...)` 静默失效** —— 真实标签带属性
   （`<head data-page-node-id="…">`）⇒ 必须 `re.subn(r'<head[^>]*>', ...)`。
6. **探针注释里写了 `</` + `script>`** ⇒ 提前闭合 `<script>` 标签，整段不执行（title 不变）。

7. **探针值不能含 `=`**（外层按 `=` 切 `k=v`）⇒ 「地形未变」只能输出 `true`，

## 地形编辑器：外部图集导入（C.3 完成，2026-09-19）

### 一、做了什么

在左栏加了「外部图集」面板，三类图可自行导入预览：**楼层图集**（地形/墙体）、
**草叶图**（`terrain_features.png` 那层）、**道具图**（`items.png`）。

`mountExt` / `refreshExtHint` / `openDB` / `dbPut` / `dbAll` / `dbDel` / `dbClear`、

### 二、三个设计约束（都写在 app.js 头部注释里）

1. **IndexedDB 而不是 localStorage**：图集 100–200KB，localStorage 只能存字符串、
   base64 膨胀 33%、配额约 5MB、还是同步 API。
2. **存 Blob 而不是 dataURL**：零膨胀。
3. **外部图集是一等公民**：与内置共用同一个 `SHEETS` 注册表、同一套 key 查找
   （key = `ext:<kind>:<name>`），UI 与 codegen 都不区分来源（只有下拉标签多个 ★）。

### 三、本轮修掉的 3 个真 bug（都是浏览器套件/桩套件抓出来的）

1. **`render()` 缺空值保护 ⇒ 首帧必崩**（C.4 就存在的，本轮回过头补）：
   `boot()` 同步、图集异步 ⇒ 首帧必定早于 `setSheets()`。C.4 把 `items.png` 内联进
   `assets.js`（216KB→332KB）**改变了时序就必炸**。修法 `if (!S.sheet) return;`。
2. **`importAtlas` 从不删除同类旧 IndexedDB 记录** ⇒ 刷新后 `restoreExt` 把新旧两条都恢复、
   **旧的排前面所以旧图赢** —— 用户看到「导入新图集后刷新，又变回旧图集了」，且 DB 无限增长。
   修法：同一循环里 `dbDel(r.key)`。
3. **启动被 IndexedDB 卡死**（最隐蔽）：`file://` 下 Edge 的 `indexedDB.open()` 可能
   **既不 `onsuccess` 也不 `onerror`** ⇒ 回调永挂。原本 `boot()` 把 `applySheet()/fullRefresh()`
   写在 `restoreExt` 回调里 ⇒ 画布 **0×0**、`Ed.E.w=14`（应 12）、**控制台一声不响**。
   修法三件套：`openDB` 加 250ms 超时 + `onblocked`；`restoreExt` 加 300ms 强制放行 + `done` 闩；
   **boot 的必需初始化改回同步**，`restoreExt` 只做追加式补充。
   定位靠临时 `_diag.html`（在 `app.js` 之后同步打印 `cvSize`/`Ed.E.w`/`boot()` 返回值），用完即删。

### 四、新增核验 `_chk/verify_atlas_import.js`（59 项，`--selftest` 61 项）

**为什么必须用桩**：浏览器里**没法自动化「从文件选择器挑一个 png」**。
桩件：真 PNG 编解码（`crc32`/`chunk`/`encodePng`/`decodePng`）+ 真 DOM 桩 +
**一张 `Map` 冒充的 IndexedDB** + `Blob`/`URL.createObjectURL`/同步解码 `Image` 桩。
覆盖 A→K：接线 / 导入 / **像素级确认真的换图** / 非 16 倍数被拒 / 同类替换 /
草叶图与道具图覆盖 / **IndexedDB 真落 Blob** / 生成代码是**人类可读名** / 清空回退 /
**模拟刷新后恢复** / 反例自测（去掉 `% 16` 校验必须被抓到）。

桩自己也踩了两个坑（已写脚本注释）：① `createObjectURL` 去重键**不能用「长度+前32字节」**
（两张同尺寸图集撞车，表现为「§E 拿到第一张图」），要用**完整 md5**；
② `revokeObjectURL` 后**必须让去重缓存失效**（否则重新导入拿到**死 URL**，`Image.onerror` ⇒ 静默失败）。

## 地形编辑器：区域随机排列（C.5 完成，2026-09-19）

### 一、做了什么

「框一块区域，生成时区域内的地形随机排布」。新增：编辑器状态 `E.randoms`（纯元数据，
**不进 `map[]`**）、区域拓扑（`addRegion` 迭代合并 / `removeRegionsIn` 整片删 / `sortRegions`）、
渲染叠加层（斜纹底 + 虚线框 + 四角标记）、codegen `emitRandomRegions`、UI 面板（2 个工具 +
开关 + 清空 + 提示行）、检查器 6f、JSON **v4**。

### 二、两条语义决策（以后改这块必读）

1. **打乱的是多重集，不是逐格重掷**：收集区域地形值（行优先）→ `Random.shuffle(int[])` →
   按同一顺序 `Painter.set` 写回。区域 5 草/2 水/1 墙，生成后配比不变、**只换位置**。
   **否决了**每格 `Random.oneOf` —— 那会把作者定的配比随机掉。
2. **区域段必须在所有地形填充之后**：它走 `Painter.set`，排在填充之前会被**整片覆盖**，
   而且**完全不报错**、字符串层面毫无异常。固定为生成流程**第 4 步**（地形后、覆盖层前）。

### 三、覆盖层联动：为什么不用 `Random.shuffle(u, v)`

三个覆盖层数组类型各不相同（`Trap[]`/`Plant.Seed[]`/`Item[]`），配上地形是四种，重载不匹配。
改用**显式置换表** `int[] ord`（初始化为恒等 → `Random.shuffle(ord)` → `r0Old = r0.clone()`
→ 各层按同一 `ord` 重排）⇒ 联动关系一眼可见，便于核验。

### 四、区域拓扑三条不变量

矩形闭区间（同 `Painter.fill` 语义）；`addRegion` **迭代合并**到稳定 ⇒ **两片永不相交**；
擦除是**整片删**（不做挖洞 —— 区域是打乱单位，残缺形状没法表达成一次 shuffle）。

### 五、本轮踩的坑（都已修 + 写进文档/技能）

1. **⚠️ 假绿：反例自测「删注释」而不「改行为」**。`--selftest` 原本只删掉「区域随机」那行段落注释，
   而 D 节断言的是 `Random.shuffle(` **所在行号** ⇒ 注释删不删都不影响 ⇒ **108/108 照样全绿**。
   修法：反例必须真的**把区域段搬到填充之前**（`indexOf` 定位发射点 + 锚点重排），
   **注入失败直接 `exit(2)`**。**假绿比红危险 —— 它让你以为有保险。**
2. **⚠️ 探针与真实路径各写一份 ⇒ 探针永远落后**。`TE_APP.markRegion` 少了 `refreshRegionHint()`，
   测试读到过期文案「当前无区域标记」，看起来像提示行坏了。修法：抽具名函数 `markRegion()`，
   拖框分支与探针**都调它**。**同一个动作绝不留两份实现。**
3. **测试硬写画布宽度 ⇒ 假红**。`regionIndices` 用 `Ed.E.w`，前面某节改过尺寸 ⇒ 硬写 `1*10+1` 失败。
   改成现取 `const W = Ed.E.w`。
4. **测试样本撞上「刻意的合并语义」⇒ 假红**。想造「1 格区域 + 一片大区域」时写成
   `(5,5,5,5)` + `(2,2,5,5)`，在 (5,5) 相撞被并成 1 片 ⇒「1 格」那条提示永远测不到。
   改成**互不相邻**的两片。

## 地形编辑器 C.6：尺寸模糊化（完成）

### 一、需求与落地

用户原话：「希望加入模糊化的功能，在开启时，房间的大小会在一定范围内变化，
并且标注此种模式不支持复杂的具体地形」。

**核心机制（静默陷阱）**：`Room.setSize(int,int,int,int)` 返回 **`boolean`**，
校验 `minW < minWidth() || maxW > maxWidth()` 不过就 `return false` 什么都不做；
而默认 `sizeCatProbs()` = `{1,0,0}` ⇒ 恒定 `NORMAL(4~10)`。
⇒ **只写 `setSize(...)` 不覆写 `sizeCatProbs()` 就是彻底的 no-op**（不报错、编译能过）。
必须**成对**：`sizeCatProbs()` 选类别（NORMAL 4~10 / LARGE 10~14 / GIANT 14~18），
`setSize(...)` 落范围。字节码验证 `setSize:(IIII)Z`。

**另两条事实**：宽高各自独立按 `NormalIntRange` **正态分布**掷（不是均匀）；
`resize()` 只改 `right`/`bottom` ⇒ **左上角不动、从右下往左上缩**。

**策略＝夹取（clamp）而非重排**：所有单元格夹进最小尺寸的安全区，逐行追加
`// ⚠ 模糊化：已夹进安全区（原 …）`。重排会毁构图且不可预测地打断连通性。

**安全区算术写两遍**（`editor.js safeRect()` 画绿框 / `codegen.js fuzzSafeRight/Bottom()` 夹坐标），
`right = min(canvas, minW) - 1 - guarded`；**关闭模糊化时两边都必须退化成整块画布**。

**单位差 2**：fuzz min/max 比 `E.w`（含外圈墙），面板显示内部尺寸。**JSON v5**（新增 `fuzz`）。
