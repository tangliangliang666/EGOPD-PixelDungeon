## 神谕代行者三处修复（解放复活保底 / 拼好饭充能 / 与你再会回能）

- **① 解放 buff 复活后不再出现**：解放（`Release`）不是 `revivePersists` ⇒ 死亡由 `Hero.live()` 摘掉；
  而保底层数的载体「业」（`Karma`，`revivePersists=true`）复活保留 ⇒ 两者必须同时存在才成立
  （`effectiveStacks() = max(自身层数, karmaFloor)`），buff 一没，`Hero` 减伤块与 `Talent.onAttackProc` 双双短路。
  解法：`Release` 抽出 `static karmaFloor(Hero)` + 新增 `static onHeroRevive(Hero)`（已有 buff 返、`karmaFloor>0` 才重挂），
  `Hero.live()` 末尾补一句调用。**没**把 buff 改成 `revivePersists=true` —— 用户要求保留「死亡清层」的语义。

- **③ Furioso「与你再会」回能**：击杀计数 `final int newKills = !enemy.isAlive() ? kills+1 : kills;` 写在
  `enemy.damage()` **之前**，而 `selectTarget()` 只挑存活单位 ⇒ 该判据恒为 true、**击杀数永远 0**；
  九次攻击全打出去时 `unused=0` ⇒ 返还 **0%**（目标少时靠 unused 还有一点，所以看起来「有时好使」）。
  改成先 `boolean wasAlive = enemy.isAlive()` → `enemy.damage(...)` → `newKills = (wasAlive && !enemy.isAlive()) ? kills+1 : kills`。

## 21:20 新武器前期调研：英雄 1~30 级基础数值曲线（未改任何玩法源码）

- **背景**：用户计划做一件「英雄 1 级 / 30 级分别进入两种特殊状态，并阻止获得任何经验」的武器，先要数值基准。
- **产出**：`docs/hero-level-progression.md`（调研报告）+ `_chk/hero_level_curve.py`（可复跑计算，同时输出 `_chk/hero_level_curve.md`）；
  `AGENTS.md` §5 内容地图登记一行。
- **核心公式（源码核对，非估算）**：`Hero.updateHT()` = `20 + 5*(lvl-1) + HTBoost`（Hero.java:286）；
  命中 = `10 + (lvl-1)`、闪避 = `5 + (lvl-1)`（初始 10/5，每次升级各 +1，Hero.java:242-243 / 2380-2381）；
  `maxExp = 5 + 5*lvl`（Hero.java:2419）。⇒ 1 级 20/10/5，30 级 **165/39/34**，全部线性、无拐点。
- **命中判定是纯比值**：`acuRoll=U(0,atk)` vs `defRoll=U(0,def)`（Char.java:810-852）⇒
  `A>=D 时 1-D/(2A)`、`A<D 时 A/(2D)`，与绝对数值无关（这是所有命中率表的算法依据）。写命中率/概率类文本时可复用。
- **唯一的非线性项是天赋点**：`tierLevelThresholds={0,2,7,13,21,31}`（Talent.java:630）⇒ 1 级 0 点 → 30 级 **29 点**；
  T3 依赖已转职（10 层天狗后）、T4 依赖已戴王冠拿到盔甲技能（`KingsCrown` 才写 `hero.armorAbility`）。**做「等级形态差」时强度差的主战场是天赋点，不是命中/闪避。**
- **与等级解耦的三件事**（做形态判据时容易踩）：力量只靠力量药剂（`Dungeon.posNeeded()` 每 5 层 2 瓶 ⇒ 到 25 层共 10 瓶、10→20）；
  武器伤害 `tier+lvl` ~ `5(tier+1)+lvl(tier+1)`；护甲 `DRMax=tier*(2+lvl)`；三者都与 hero 等级无关。
- **经验阻断落点**：唯一收口 `Hero.earnExp()`（Hero.java:2315，`Mob.die()` 于 Mob.java:882 调用）。
  在该方法开头 return 会**连坐**神器充能（EtherealChains/HornOfPlenty/AlchemistsToolkit/MasterThievesArmband/Berserk）、
  `onHeroGainExp` 回调、三个天赋计数器 —— 已写进报告第 6 节，开发时需先决定要不要保留这些收益。
- **两个易错认知**：① `Mob.maxLvl` 默认 = `MAX_LEVEL-1 = 29`（Mob.java:141）⇒ **1 级英雄打怪照样拿全额经验**，
  「阻止经验」必须武器自己拦；② 30 级后 `earnExp` 的 while 走 else 分支，本来就把经验清 0 只给 `Bless`（Hero.java:2383-2390），
  所以 30 级形态的「阻止经验」实际只是拦祝福 buff，重点应放在形态强度。

## 三、**新发现的框架级陷阱**：`Char.buff(Class)` 是精确类匹配

把渴望的护盾从 `Barrier` 换成子类 `ThirstBloodBarrier` 后才查清：`Char.buff(Class)` 用 **`b.getClass() == c`**
（方法上方注释就写着「Not just assignable」），**不是** `isInstance`；`Buff.affect(t, cls)` 也走它。
⇒ 身上已有「基类实例」时传子类会**另建一份**：buff 栏出现**两个 ARMOR 图标**，且所有 `hero.buff(Barrier.class)`
判定都**看不见**它（`Dewdrop`/`Waterskin` 的护盾限量、`Blocking`/`NarcissusShield.fx` 的「还有没有护盾」、`Barrier.fx` 摘 SHIELDED）。
**但伤害吸收不受影响** —— `ShieldBuff.processDamage` 走 `target.buffs(ShieldBuff.class)`，那是 `isInstance`。
取舍：选「语义精确 + 改动局部」，把代价**如实写进类注释「已知代价」一节**并钉成断言（`verify_artifact_enhance.py` §D）。
已同步 `AGENTS.md` §6 与 `MEMORY.md`。
